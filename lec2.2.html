מה זה GROUP BY? — קודם מבינים, אחר כך קוד

📖 השאלה העסקית שמחייבת GROUP BY

מנכ"ל EHI שואל: "כמה עובדים יש בכל מחלקה? מה ממוצע ציון האושר בכל מחלקה?"

הבעיה: טבלת employees מכילה שורה אחת לכל עובד. אין שורה שאומרת "ממוצע מחלקת מכירות". אנחנו צריכים לבקש מ-SQL לאסוף שורות לפי קבוצות ולחשב על כל קבוצה.

בדיוק לכך משמש GROUP BY.

💡 האנלוגיה: מיון כרטיסיות לערמות

דמיינו שיש לכם 5 כרטיסיות על השולחן — אחת לכל עובד. על כל כרטיסייה: שם, מחלקה, וציון אושר.

GROUP BY זה כאילו אתם מסדרים את הכרטיסיות לפי מחלקה — ערמה אחת למכירות, ערמה לטכנולוגיה, ערמה ל-HR. אחרי המיון — אתם יכולים לחשב על כל ערמה: כמה כרטיסיות? מה הממוצע?

💡 הכלל הזהב של GROUP BY: מה מותר ב-SELECT?

כשמשתמשים ב-GROUP BY, ב-SELECT מותר לכתוב רק שתי סוגי דברים:

1. העמודות שנמצאות ב-GROUP BY (כמו dept_name)

2. פונקציות אגרגציה — COUNT(), SUM(), AVG(), MAX(), MIN()

שגיאה נפוצה: לכתוב ב-SELECT עמודה שלא ב-GROUP BY ולא בפונקציה — SQL יתלונן!

הקוד המלא — מילה אחר מילה

💻 שאילתת GROUP BY מלאה — פירוק מוחלט

הנה שאילתה מלאה שמחשבת לכל מחלקה: כמה עובדים, ממוצע אושר, וסכום ההשקעות. נפרק כל מילה:

SELECT
    dept_name,
    COUNT(*) AS num_employees,
    AVG(happiness_score) AS avg_happiness,
    SUM(total_investment) AS total_spent
FROM employees_summary
GROUP BY dept_name
ORDER BY avg_happiness DESC;
🔍 פירוק שורה-שורה — לא נשאיר שום דבר לא מוסבר
SELECT dept_name
dept_name היא עמודת הקיבוץ. כי כתבנו GROUP BY dept_name, מותר לנו לכתוב dept_name ב-SELECT. אם כתבנו ב-SELECT עמודה אחרת (כמו full_name) שאינה ב-GROUP BY ואינה בפונקציה — SQL יזרוק שגיאה.
COUNT(*) AS num_employees
COUNT(*) = "ספור את מספר השורות בכל קבוצה". AS num_employees = שם לעמודה בתוצאה. AS הוא "כינוי לעמודה" — במקום שעמודה תיקרא "COUNT(*)" (מכוער), נקראת "num_employees" (ברור).
AVG(happiness_score)
AVG = Average = ממוצע. SQL ייקח את כל ערכי happiness_score בקבוצה, ויחשב את ממוצעם. לדוגמה: מחלקת מכירות עם 8.2 ו-5.1 → ממוצע (8.2+5.1)/2 = 6.65.
SUM(total_investment)
SUM = סכום. SQL ייקח את כל ערכי total_investment בקבוצה וימיין אותם. לדוגמה: מחלקת מכירות עם 3,000 + 25,000 + 8,000 = 36,000.
GROUP BY dept_name
זו הפקודה המרכזית. אומרת ל-SQL: "אסוף את כל השורות שיש להן אותה dept_name לקבוצה אחת, ואז חשב את הפונקציות על כל קבוצה". בלי GROUP BY — הפונקציות יחשבו על כל הטבלה כולה (ויחזירו שורה אחת).
ORDER BY avg_happiness DESC
ORDER BY = מיין את התוצאות. DESC = מהגבוה לנמוך (Descending). ASC = מהנמוך לגבוה (Ascending). אחרי GROUP BY, אפשר למיין לפי כל עמודת תוצאה — כולל עמודות שחישבנו כמו avg_happiness.
🎯 מה ההבדל בין ROUND() ל-AVG()?

AVG מחשב ממוצע אבל עשוי להחזיר מספרים ארוכים כמו 6.650000000001. כדי לעגל ל-2 ספרות אחרי הנקודה, עוטפים ב-ROUND: ROUND(AVG(happiness_score), 2). הספרה 2 אומרת "עגל ל-2 ספרות אחרי הנקודה".

🎯 המשימה: דוח סיכום מחלקות כתבו שאילתת GROUP BY שמחשבת לכל מחלקה:
  • dept_name — שם המחלקה (עמודת הקיבוץ)
  • COUNT(*) AS num_employees — כמה עובדים
  • ROUND(AVG(happiness_score), 2) AS avg_happiness — ממוצע ציון אושר
  • SUM(intervention_cost) AS total_spent — סך ההשקעה
  • מיינו מהמחלקה הכי מאושרת (avg_happiness גבוה → נמוך)
SELECT dept_name, COUNT(*) AS num_employees,
  ROUND(AVG(happiness_score), 2) AS avg_happiness,
  SUM(intervention_cost) AS total_spent
FROM ehi_summary
GROUP BY dept_name
ORDER BY avg_happiness DESC;

GROUP BY על שתי עמודות — "חיתוך עמוק"

🔀 מתי צריך לקבץ לפי שתי עמודות?

שאלה עסקית מורכבת יותר: "מה ממוצע ציון האושר לפי מחלקה וגם לפי סוג ההתערבות?"

עם GROUP BY על עמודה אחת נקבל 3 שורות (מחלקה). אבל אם נרצה לראות כל שילוב של מחלקה + סוג התערבות — נשתמש ב-GROUP BY על שתי עמודות.

💡 האנלוגיה: מיון לפי שתי תיוות

חזרו לדוגמת הכרטיסיות. קודם מיינתם לפי מחלקה. עכשיו, בתוך כל ערמת מחלקה — תמיינו שוב לפי סוג ההתערבות.

תוצאה: ערמה "מכירות + מנוי גים", ערמה "מכירות + ריטריט", ערמה "טכנולוגיה + מנוי גים", וכן הלאה.

הקוד — GROUP BY על שתי עמודות

SELECT
    dept_name,
    intervention_type,
    COUNT(*) AS num_times,
    SUM(cost) AS total_cost,
    ROUND(AVG(roi_score), 2) AS avg_roi
FROM happiness_interventions_full
GROUP BY dept_name, intervention_type
ORDER BY total_cost DESC;

-- GROUP BY על שתי עמודות: מפריד את הוקבוצות
-- לכל שילוב ייחודי של (dept_name, intervention_type)
💡 הכלל: כל עמודה ב-SELECT שאינה בפונקציה — חייבת ב-GROUP BY

כשכותבים SELECT dept_name, intervention_type, SUM(cost) — שתי העמודות dept_name ו-intervention_type חייבות להיות ב-GROUP BY. רק cost נמצא בפונקציה ולכן אינו חייב.

HAVING — איך מסננים אחרי שקיבצנו?

🤔 הבעיה: WHERE לא עובד על תוצאות GROUP BY

נניח שגמרנו לחשב ממוצע אושר לכל מחלקה. עכשיו המנכ"ל אומר: "הראה לי רק מחלקות שממוצע האושר שלהן נמוך מ-7.5 — אלה בסיכון."

הבעיה: WHERE avg_happiness < 7.5 לא יעבוד! כי WHERE פועל לפני GROUP BY — ב-WHERE עדיין אין עמודת avg_happiness, כי היא נוצרת רק אחרי הקיבוץ.

הפתרון: HAVING — פקודה שמסננת אחרי GROUP BY.

סדר הביצוע של SQL — זה קריטי!

1. FROM
→
2. WHERE
(מסנן שורות בודדות)
→
3. GROUP BY
→
4. HAVING
(מסנן קבוצות)
→
5. SELECT
→
6. ORDER BY
⚠️ הכלל הזהב: WHERE לפני GROUP BY, HAVING אחרי

WHERE — מסנן שורות בודדות לפני הקיבוץ. לדוגמה: "תסנן רק התערבויות שה-cost שלהן מעל 5,000" — עדיין שורות בודדות.

HAVING — מסנן קבוצות שלמות לאחר הקיבוץ. לדוגמה: "תסנן מחלקות שה-AVG(happiness) שלהן נמוך מ-7.5" — כאן מדובר בקבוצות, לא בשורות.

השוואה: WHERE לעומת HAVING — מה השוני?

❌ שגוי: WHERE לא מכיר avg_happiness
SELECT dept_name,
  AVG(happiness_score) AS avg_happiness
FROM employees
WHERE avg_happiness < 7.5  -- ❌ שגוי!
GROUP BY dept_name;

SQL יזרוק שגיאה: avg_happiness לא קיים בשלב ה-WHERE. הוא נוצר רק ב-GROUP BY שמגיע אחר כך.

✅ נכון: HAVING מסנן אחרי GROUP BY
SELECT dept_name,
  AVG(happiness_score) AS avg_happiness
FROM employees
GROUP BY dept_name
HAVING AVG(happiness_score) < 7.5;  -- ✅

HAVING מגיע אחרי GROUP BY ולכן מכיר את הערכים המחושבים. שימו לב: ב-HAVING כותבים AVG(happiness_score) ולא avg_happiness.

📚 סיכום פרק 2 — מה למדנו

1
GROUP BY — מיון לערמות ואז חישוב

מאסף שורות עם ערך משותף לקבוצה אחת, ומאפשר לחשב פונקציות (SUM, AVG, COUNT) על כל קבוצה. התוצאה: שורה אחת לכל קבוצה.

2
פונקציות אגרגציה — COUNT, SUM, AVG, MAX, MIN

כל אחת מחשבת משהו שונה על הקבוצה. COUNT(*) = כמה שורות, SUM = סכום, AVG = ממוצע, MAX/MIN = קצוות.

3
GROUP BY על מספר עמודות — חיתוך עמוק

כמה עמודות ב-GROUP BY = כמה עמודות ב-SELECT שאינן בפונקציה. כל שילוב ייחודי הופך לקבוצה.

4
HAVING — לסנן אחרי הקיבוץ

WHERE מסנן שורות לפני GROUP BY. HAVING מסנן קבוצות לאחר GROUP BY. לסינון על ערכים מחושבים — תמיד HAVING.

5
סדר הכתיבה: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY

SQL ביצוע: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. הסדר חשוב — לא ניתן להשתמש ב-avg_happiness ב-HAVING אלא ב-AVG(happiness_score) כי הכינוי עדיין לא קיים בשלב ה-HAVING.

🎓 הפרק הבא: CASE WHEN, COALESCE & תאריכים

בפרק 3 נלמד לוגיקה מתקדמת: לסווג עובדים ל"רמות סיכון" אוטומטית עם CASE WHEN, לטפל ב-NULLs עם COALESCE, ולעבוד עם תאריכים — כמו "כמה הוצא בכל חודש?" כל זאת תוך שמירה על אותה גישה: קודם ויזואלי, אחר כך קוד.
