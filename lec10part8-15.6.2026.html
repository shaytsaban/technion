מה זה CTE? תוצאת ביניים עם שם

CTE (אותו WITH שראית) = לחשב משהו, לתת לו שם זמני, ואז לשאול עליו שאלה. כמו להגדיר עוזר לפני החישוב הראשי. לפניך CTE — לחץ כדי להכיר את שלושת חלקיו:

WITH cat AS (
  SELECT category, SUM(sale_price) AS revenue
  FROM order_items GROUP BY category
)
SELECT * FROM cat WHERE revenue > 1000;
🔎 לחץ כדי להאיר כל חלק
לחץ על כפתור כדי לראות הסבר והדגשה ←
למה בכלל צריך שלב ביניים? כי יש שאלות שאי אפשר לענות עליהן בשאילתה אחת שטוחה.

② הבעיה

שאלה שדורשת שני שלבים

המנהל שואל: "אילו קטגוריות מכרו מעל ההכנסה הממוצעת של קטגוריה?" אי אפשר בשאילתה אחת שטוחה — כי כדי לדעת את הממוצע, קודם צריך לחשב את ההכנסה של כל קטגוריה. זה תהליך בשלבים:

🧩 לחץ לפרק את השאלה לשלבים
1
חשב הכנסה לכל קטגוריה (זו תוצאת הביניים — ה-CTE)
2
חשב את הממוצע של ההכנסות האלה
3
השאר רק קטגוריות מעל הממוצע
שלב 1 חייב לקרות לפני שלב 2 — אי אפשר לחשב ממוצע של דבר שעוד לא חישבת. לכן צריך לתת לתוצאת שלב 1 שם, ולהשתמש בו. זה בדיוק CTE.
יש שתי דרכים לכתוב שלב ביניים — CTE קריא, או תת-שאילתה מקוננת. נכיר את שתיהן.
פרק את השאלה לשלבים

CTE מול תת-שאילתה — אותו דבר, שתי כתיבות

שתיהן מחשבות תוצאת ביניים. CTE נותן לה שם למעלה ואז משתמש בו — קריא, ומתאים לשרשור שלבים. תת-שאילתה מקננת את אותו חישוב בתוך השאילתה — מהיר וקצר, אבל פחות קריא כשיש כמה שלבים.

🏷️ זהה כל קטע — CTE או תת-שאילתה?
WITH cat AS (SELECT ...)
SELECT * FROM cat;
SELECT * FROM (
  SELECT ... FROM order_items
);

זהה את שני הקטעים.

כלל אצבע: שלב אחד פשוט → תת-שאילתה זה בסדר. שניים או יותר → CTE, כי אפשר לשרשר ולתת שם לכל שלב. WITH a AS (...), b AS (...) — ו-b יכול להשתמש ב-a.
מספיק תיאוריה — נכתוב CTE אמיתי ב-BigQuery, ונראה שהוא זהה לתת-שאילתה.
זהה את שני הקטעים
④ BigQuery · CTE = תת-שאילתה ☁️

אותה תוצאה, שתי כתיבות

נחשב הכנסה לכל קטגוריה כתוצאת ביניים, ונציג את 5 המובילות — פעם עם CTE, פעם עם תת-שאילתה. אותה תוצאה בדיוק.

  1. פתח את BigQuery Sandbox והתחבר עם חשבון Google.
  2. הרץ את שאילתה א' (CTE) ואת שאילתה ב' (תת-שאילתה). התוצאה זהה.
א' · עם CTE (קריא)
WITH cat AS (
  SELECT p.category, SUM(oi.sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
  JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
  GROUP BY p.category
)
SELECT category, ROUND(revenue) AS revenue
FROM cat
ORDER BY revenue DESC
LIMIT 5;
ב' · עם תת-שאילתה (אותה תוצאה)
-- אותו חישוב, מקונן בתוך ה-FROM
SELECT category, ROUND(revenue) AS revenue
FROM (
  SELECT p.category, SUM(oi.sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
  JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
  GROUP BY p.category
)
ORDER BY revenue DESC
LIMIT 5;

צעד אחד זה קל. הכוח האמיתי של CTE הוא בשרשור כמה שלבים — בדיוק ה"מעל הממוצע".

⑤ BigQuery · שרשור שלבים ☁️

CTE אחד מזין את הבא — "מעל הממוצע"

עכשיו נפתור את שאלת המנהל מצעד ②: שני CTE-ים משורשרים — הראשון מחשב הכנסה לכל קטגוריה, השני מחשב את הממוצע שלהם, והשאילתה הראשית משווה.

  1. הרץ את שאילתה ג' — קטגוריות מעל ההכנסה הממוצעת.
  2. הרץ את שאילתה ד' — אותו רעיון על חודשים: חודשים מעל ההכנסה החודשית הממוצעת.
ג' · קטגוריות מעל הממוצע
-- שלב 1: הכנסה לכל קטגוריה. שלב 2: הממוצע. ראשית: סינון מעל הממוצע.
WITH cat AS (
  SELECT p.category, SUM(oi.sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
  JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
  GROUP BY p.category
),
avg_rev AS (
  SELECT AVG(revenue) AS avg_revenue FROM cat
)
SELECT c.category, ROUND(c.revenue) AS revenue
FROM cat c, avg_rev
WHERE c.revenue > avg_rev.avg_revenue
ORDER BY revenue DESC;
ד' · חודשים מעל ההכנסה החודשית הממוצעת
WITH monthly AS (
  SELECT DATE_TRUNC(DATE(created_at), MONTH) AS month,
    SUM(sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items`
  GROUP BY month
),
stats AS (
  SELECT AVG(revenue) AS avg_rev FROM monthly
)
SELECT m.month, ROUND(m.revenue) AS revenue
FROM monthly m, stats
WHERE m.revenue > stats.avg_rev
ORDER BY m.month;
✅ כל CTE הוא שלב נקי עם שם. השאילתה נקראת מלמעלה למטה כמו מתכון: חשב X, חשב Y, ואז שלב סופי. זה הסוד לכתוב שאילתות מורכבות בלי ללכת לאיבוד.

יש עוד מקום שבו תת-שאילתה זורחת: בתוך תנאי הסינון עצמו — WHERE.

⑥ BigQuery · תת-שאילתה בסינון ☁️

לסנן לפי ערך שצריך לחשב קודם

לפעמים תנאי הסינון עצמו דורש חישוב: "מעל הממוצע", "בקטגוריות היקרות". תת-שאילתה בתוך WHERE מחשבת את הערך הזה תוך כדי.

  1. הרץ את שאילתה ה' — פריטים שמחירם מעל המחיר הממוצע (תת-שאילתה שמחזירה מספר אחד).
  2. הרץ את שאילתה ו' — מוצרים מקטגוריות "יקרות" (תת-שאילתה שמחזירה רשימה, עם IN).
ה' · פריטים מעל המחיר הממוצע
-- התת-שאילתה בסוגריים מחשבת מספר אחד: המחיר הממוצע
SELECT id, sale_price
FROM `bigquery-public-data.thelook_ecommerce.order_items`
WHERE sale_price > (
  SELECT AVG(sale_price) FROM `bigquery-public-data.thelook_ecommerce.order_items`
)
ORDER BY sale_price DESC
LIMIT 10;
ו' · מוצרים מקטגוריות יקרות (IN)
-- התת-שאילתה מחזירה רשימת קטגוריות; ה-IN מסנן לפיה
SELECT name, retail_price, category
FROM `bigquery-public-data.thelook_ecommerce.products`
WHERE category IN (
  SELECT category
  FROM `bigquery-public-data.thelook_ecommerce.products`
  GROUP BY category
  HAVING AVG(retail_price) > 50
)
LIMIT 10;
✅ תת-שאילתה שמחזירה מספר אחד → משווים אליו עם > או <. תת-שאילתה שמחזירה רשימה → מסננים לפיה עם IN.

סיימת — עכשיו אתה כותב שאילתות מורכבות

  • CTE (WITH name AS (...)) = תוצאת ביניים עם שם
  • תת-שאילתה = אותו רעיון, מקונן בתוך השאילתה
  • שלב אחד פשוט → תת-שאילתה · כמה שלבים → CTE משורשר
  • תת-שאילתה ב-WHERE: מספר אחד → השוואה (>) · רשימה → IN
  • שרשור CTE = לקרוא שאילתה מורכבת כמו מתכון, שלב-שלב
