🧭 מקרא: חמשת סוגי הקופסאות שילוו אתכם

כדי שתמיד תדעו "מה אני אמור לעשות עם הקטע הזה", כל ההרצאה משתמשת בחמש קופסאות קבועות:

קופסת קוד שחורה — תוכן להעתקה. תמיד קובץ שלם או רצף פקודות שלם. לוחצים "העתק", מדביקים כמו שהוא. אף פעם לא "להוסיף באמצע".
חלון דמה (מסגרת חלון) — "מה אמורים לראות" על המסך אחרי הפעולה. משווים אליו כדי לוודא שהכל תקין.
קופסת "מה זה אומר" כחולה — עצירה קצרה שמסבירה מה בעצם קרה עכשיו ולמה זה חשוב לפאזל.
נקודת ביקורת ירוקה — הבדיקה שמאשרת שהשלב הצליח. עוברים אותה ← ממשיכים בראש שקט.
"אם משהו השתבש" צהובה — טבלת תקלות נפוצות: מה רואים ← מה הסיבה ← מה הפתרון.
👩‍🏫 הערת אתי חשוב לפני שממשיכים: מכאן והלאה, כל מה שנעשה — כתיבת קוד, הרצתו, שמירת קבצים, פרסום לאינטרנט — יקרה בתוך הדפדפן, בענן. לא תתקינו Node.js, לא Git, ולא שום תוכנה אחרת על המחשב. לכן גם אין שום הבדל בין Windows ל-Mac — כשהכל קורה בדפדפן, סוג המחשב פשוט לא משנה. ההבדל היחיד: במקומות שבהם על Windows לוחצים Ctrl, על Mac לוחצים Cmd ⌘ — ונציין את זה בכל פעם שזה רלוונטי.

🍽️ המסעדה: שלושה חדרים, שלושה תפקידים

כל אתר אינטרנט בעולם — כולל "תקציבי אביב" — בנוי משלושה חלקים נפרדים, כמו מסעדה עם שלושה חדרים. זו האנלוגיה היחידה שתצטרכו היום, ונחזור אליה בכל תחנה:

🪑 חדר האוכל — מה שהמשתמש רואה

השולחנות, התפריט, העיצוב. זה ה-Frontend — כל מה שרואים ולוחצים עליו בדפדפן. אצלנו: הדף עם הכרטיסים והטופס שראיתם בבלוק 1.

🍳 המטבח — איפה שקורית העבודה

מקבל הזמנות, מחליט מה לעשות, מחזיר תוצאה. זה ה-Backend — תוכנית שרצה מאחורי הקלעים, בלי שהלקוח רואה אותה. אצלנו: קובץ בשם server.js.

🥫 המחסן — איפה שהכל נשמר

מדפים מסודרים של מלאי, עם מנהל קפדני שיודע בדיוק מה יש ואיפה. זה ה-Database (מסד הנתונים) — אצלנו: PostgreSQL. שימו לב לכלל הברזל של מנהל המחסן: הוא לא מדבר עם לקוחות. אף פעם. הוא עונה רק למטבח, ורק בשפה המקצועית שלו — SQL.

📄 רגע, מאילו קבצים מורכב "חדר האוכל"?

כשדפדפן פותח אתר, בדרך כלל נטענים שלושה סוגי קבצים. חשוב להכיר אותם בשמם כי תפגשו אותם בכל מקום:

📃 HTML — "השלד"

רק התוכן והמבנה: אילו כותרות, אילו כפתורים, אילו שדות. כמו תפריט שכתוב על דף לבן פשוט — רק המילים.

🎨 CSS — "העיצוב"

איך הדברים נראים: צבעים, גופנים, מרווחים. אותו תפריט, עכשיו עם גופן יוקרתי ומסגרת מוזהבת.

⚡ JavaScript — "ההתנהגות"

קוד שרץ בתוך הדפדפן ומגיב ללחיצות. כשלוחצים "רישום ההוצאה", הוא זה ש"אורז" את הפרטים ושולח אותם למטבח — כמו מלצר שרושם פתק ומעביר אותו, בלי לבשל בעצמו.

💡 באפליקציה שנבנה היום, שלושת אלה יגיעו יחד בקובץ אחד שהשרת מגיש — כדי שיהיה לכם קובץ אחד בלבד לנהל. באתרים גדולים הם קבצים נפרדים (index.html, styles.css, app.js) — אותו רעיון בדיוק, רק מפוצל.

🍳 אז מה זה בדיוק "שרת" (Server)?

שרת הוא תוכנית שיושבת דלוקה 24 שעות ביממה, מחכה שיגיעו אליה בקשות מהאינטרנט, ועונה עליהן. זהו. זו כל ההגדרה. המטבח של המסעדה: פתוח תמיד, מחכה לפתקים, מבצע, מחזיר. אצלנו התוכנית הזו תיכתב בקובץ אחד בשם server.js.

🎩 הערת מיסטר אולאף למה קוראים לקובץ server.js? שני חלקים: הסיומת .js היא חובה — היא אומרת "זהו קובץ בשפת JavaScript", כמו ש-.jpg אומר "זו תמונה". השם server שלפני הנקודה הוא רק מוסכמה נוחה — אפשר היה לקרוא לו גם muffin.js והכל היה עובד, כי ממילא אומרים למחשב במפורש איזה קובץ להריץ (node server.js). בוחרים שם שמסביר את התפקיד, כדי שמתכנת אחר יבין מיד.

⚙️ ומי מריץ את הקובץ הזה? Node.js ו-Express

JavaScript נולדה כשפה שרצה רק בתוך דפדפנים. Node.js הוא תוכנה שמשחררת את השפה מהדפדפן — ומאפשרת להריץ אותה כתוכנית עצמאית על כל מחשב, כולל שרת שיושב ומחכה לבקשות. ו-Express? זו ספריית עזר שרצה על גבי Node.js וחוסכת לנו את כל העבודה השחורה של "איך בכלל מקשיבים לבקשות מהאינטרנט".

🔥 האנלוגיה: אספקת גז מול מטבח מאובזר

Node.js = חיבור הגז למטבח: הכוח שמאפשר לבשל בכלל, אבל בלי כיריים ובלי כלים. Express = ציוד המטבח המוכן שבנוי סביב הגז: כיריים, טיימרים, משטחים. שניהם יחד = מטבח שאפשר לעבוד בו מיד. שניהם חינמיים לגמרי, ושניהם כבר יחכו לנו מותקנים-או-מוכנים-להתקנה בתחנה הבאה.

🚪 ולמה מסד נתונים לבד לא מספיק? (הנקודה הכי חשובה בבלוק)

עכשיו אפשר לענות במדויק: מנהל המחסן (PostgreSQL) הוא גאון במה שהוא עושה — שמירה, חיפוש, חישוב. אבל אין לו דלת לרחוב: הוא לא יודע לקבל בקשות מהאינטרנט, לא מבין מה דפדפן רוצה ממנו, לא בודק אם מותר למישהו לבקש משהו. הוא מדבר רק עם מי שנכנס אליו פנימה, ורק ב-SQL.

לכן חייבים מישהו באמצע: תוכנית שדלתה כן פונה לרחוב, שמדברת "אינטרנט" מול הלקוחות ו-SQL מול המחסן. זו בדיוק ההגדרה של שרת — וזו הסיבה שתחנה 3 (שרת) באה לפני תחנה 4 (מסד נתונים): קודם בונים את מי שיודע לדבר עם העולם, ורק אז מחברים לו מחסן.

🐘 ולמה דווקא PostgreSQL, ולא מנהל מחסן אחר?

יש הרבה מסדי נתונים בעולם, ו-PostgreSQL הוא רק אחד מהם — אבל אהוב במיוחד: חינמי וקוד-פתוח, עוצמתי מאוד, עובד זהה בכל מקום, ועם קהילה ענקית שכבר ענתה כמעט על כל שאלה. Apple, Spotify ו-Instagram משתמשות בו בקנה מידה עצום.

הוא לא היחיד: MySQL דומה ופופולרי לא פחות, SQL Server של מיקרוסופט נפוץ מאוד בארגונים ישראליים, ו-Oracle שולט בבנקים. יש גם משפחה אחרת לגמרי (NoSQL, כמו MongoDB). ההבדלים העמוקים ומתי בוחרים מה — זה התחום שד"ר קונדילה 👨‍🏫 יורד אליו לעומק בקורס. להיום מספיק לדעת: כולם "מנהלי מחסן" קפדניים שמדברים רק דרך שרת.

🔌 איך המטבח קורא את הפתק: כתובות ופעלים (REST API)

נשארנו עם שאלה אחת פתוחה: כשמגיע פתק למטבח, איך השרת יודע מה בדיוק מבקשים ממנו? התשובה: לכל פתק יש בדיוק שני פרטים.

1️⃣ קודם הרעיון, בשפה יומיומית

כל בקשה שמגיעה לשרת מורכבת מ: (א) על מה מדובר — כתובת, ו-(ב) מה לעשות עם זה — פעולה. בדיוק כמו פתק במסעדה: "שולחן 5" (על מה) + "תוסיף מנה" (מה לעשות). הנה שלוש בקשות אמיתיות מ"תקציבי אביב":

מה הלקוח רוצה (בעברית)(א) על מה מדובר — הכתובת(ב) מה לעשות
"תראה לי כמה כסף נשאר"/api/summaryתן לי מידע
"תרשום שהוצאתי 45 דולר"/api/expensesצור משהו חדש
"תמחק את הוצאה מספר 3"/api/expenses/3מחק
👩‍🏫 הערת אתי שאלה שכולם שואלים כאן: מאיפה הגיע השם /api/expenses? משום מקום רשמי! זה לא תקן עולמי ולא חוק. מי שכותב את האפליקציה בוחר את השמות — כמו שמות לתאי דואר בבניין. אפשר היה לבחור /money-stuff והכל היה עובד. הדבר היחיד שחשוב: שהצד ששולח (הדף בדפדפן) והצד שמקבל (server.js) מסכימים מראש על אותו שם בדיוק — אחרת הפתק מגיע לתא דואר לא קיים, ושום דבר לא קורה.

2️⃣ עכשיו השמות הרשמיים: Endpoint, Method, ו-REST

לשיטה המסודרת הזו קוראים REST API. "(א) הכתובת" נקראת נקודת קצה (Endpoint), ו"(ב) הפעולה" נקראת פועל (Method). יש ארבעה פעלים עיקריים, והנה כל מה שהמערכת שלנו תדע לעשות — כל שורה בטבלה תהפוך בתחנות הבאות לכמה שורות קוד:

פועל (Method)כתובת (Endpoint)מה זה עושה אצלנו
GET/תן לי את הדף עצמו (חדר האוכל)
GET/api/summaryתן לי את התקציב, הניצול והיתרה
GET/api/expensesתן לי את כל רשימת ההוצאות
POST/api/expensesצור הוצאה חדשה
DELETE/api/expenses/:idמחק הוצאה לפי המספר שלה

כלל אצבע לזכור: GET = "תן לי" (לא משנה כלום). POST = "צור חדש". PUT = "עדכן קיים". DELETE = "מחק".

📖 ההגדרה שצריך לזכור: מה זו "נקודת קצה" (Endpoint)?

נקודת קצה = כלל בודד שכתוב בקוד השרת, שאומר: "אם הגיעה בקשה מהפועל הזה, לכתובת הזו — בצע את הפעולה הזו". השרת שלנו יכיל חמש נקודות קצה — בדיוק כמו חמש השורות בטבלה. אתרים גדולים מכילים מאות. זה "התפריט הפנימי" של מה שהמטבח יודע להכין.

🔭 ומה עם הקוד? בכוונה עוד לא ראינו שורת קוד אחת. את נקודת הקצה הראשונה שלכם תכתבו בעצמכם בתחנה 3 (בלוק 4), אחרי שיהיה לכם מחשב ענן ביד — ואז נפרק אותה שורה-שורה. ככה כשתקלידו אותה, כבר תדעו בדיוק מה אתם מקלידים ולמה.

Node.js הוא אחת הטכנולוגיות הנפוצות ביותר בהייטק הישראלי — Wix, Fiverr ו-Monday.com נשענות עליו בחלקים נרחבים מהמערכות שלהן. הסיבה: שפה אחת (JavaScript) גם ל-Frontend וגם ל-Backend מקצרת פיתוח וגיוס.

🤔 למה לא פשוט להתקין הכל על המחשב שלי?

אפשר, וזו הדרך המקובלת בתעשייה. אבל בכיתה עם עשרות מחשבים שונים — Windows, Mac, ולפעמים Chromebook — ההתקנות עצמן הופכות לשיעור שלם של תקלות: לכל אחד גרסה אחרת, הרשאה אחרת, שגיאה אחרת. הפתרון: כולם מקבלים את אותו מחשב בדיוק — מחשב וירטואלי בענן של גוגל, שנפתח בתוך הדפדפן, עם כל הכלים כבר מותקנים. זה נקרא Google Cloud Shell.

💡 מה זה בעצם "טרמינל"? (מניחים אפס ידע, כמו שהבטחנו)

טרמינל (Terminal) הוא חלון שבו מדברים עם המחשב בפקודות טקסט במקום בלחיצות עכבר. כותבים פקודה, לוחצים Enter, המחשב מבצע ומדפיס תשובה. למה מתכנתים אוהבים אותו? כי פקודה כתובה היא מדויקת, ניתנת להעתקה, וזהה אצל כולם — בדיוק מה שצריך בהרצאה כמו שלנו. כל הפקודות היום יגיעו מוכנות להעתקה, עם הסבר מה כל שורה עושה.

  • Node.js, npm ו-Git כבר מותקנים — שלושת הכלים שנצטרך, בלי להתקין דבר

  5. 🎯 שלב 3.5 · מדביקים את הקוד — קובץ שלם, מוסבר שורה-שורה

    מה עושים: לוחצים "העתק" על הקופסה למטה ← לוחצים בתוך הקובץ הריק בעורך ← מדביקים (Ctrl+V / Cmd+V) ← שומרים (Ctrl+S ב-Windows / Cmd+S ב-Mac).

    מה הקטע: זהו שרת שלם ואמיתי — 17 שורות בלבד, שלושה חלקים. זה בדיוק המבנה שלמדנו בבלוק 2, עכשיו בקוד:

    JAVASCRIPT · תוכן הקובץ server.js — קובץ שלם, מחליף כל מה שבקובץ
    // server.js — the first server you will ever run. 3 parts, that's all.

// part 1: load the Express toolkit (we installed it with: npm install express)
// and create "app" — the object that represents our whole server
const express = require('express');
const app = express();

// part 2: ONE rule (an "endpoint"): when a browser asks for the
// home address "/", send back a small JSON answer
app.get('/', (req, res) => {
  res.json({ message: 'שלום! אני שרת אמיתי, ואני רץ בענן' });
});

// part 3: start listening on door number 8080, and never stop
app.listen(8080, () => {
  console.log('השרת פועל ומאזין על פורט 8080');
});
    🧠 הקוד, שורה-שורה, במילים של בלוק 2

    חלק 1 — require('express'): "תביא לי את ציוד המטבח שהתקנו בשלב 3.3". ואז express() יוצר את app — האובייקט שמייצג את השרת כולו, המטבח שלנו.

    חלק 2 — app.get('/', ...): זו נקודת קצה — הכלל הבודד הראשון שלכם! בעברית: "כשמגיעה בקשת GET לכתובת הראשית /, הרץ את הקוד הזה". והקוד — res.json(...) — פשוט שולח תשובה קצרה חזרה למי ששאל.

    חלק 3 — app.listen(8080, ...): השורה שהופכת קוד רגיל לשרת. היא אומרת: "התיישב ליד דלת מספר 8080, ואל תפסיק להקשיב". בלעדיה — התוכנית הייתה מסתיימת מיד. 8080 הוא "מספר דלת" (פורט) — מוסכמה נפוצה, אין בו קסם.

    ו-req, res? שני "עוזרים" ש-Express מגיש לנו בכל בקשה: req (request) מכיל את כל פרטי הבקשה שהגיעה; res (response) הוא הכלי לשלוח תשובה חזרה.

    💾 איך יודעים שהקובץ נשמר?

    כשיש שינויים לא-שמורים, מופיעה נקודה עגולה על לשונית הקובץ למעלה. אחרי שמירה מוצלחת הנקודה נעלמת (חוזר סימן ה-✕ הרגיל). התרגלו להציץ בה אחרי כל שמירה — "שכחתי לשמור" היא תקלת מתחילים מספר 1 בעולם.

    🧠 עצרו הכל. בואו נבין מה בדיוק קרה כאן — כי קרה כאן משהו גדול

    על המסך מופיעה שורה אחת קטנה, וקל לחשוב "זהו?? בשביל זה עבדתי?". אז לא — השורה ה"משעממת" הזו היא רגע חניכה. הנה מה שבאמת התרחש, בשניות האחרונות, לפי תרשים חמשת השלבים:

    1️⃣ הדפדפן שלכם (חדר האוכל) שלח בקשת HTTP אמיתית — פתק "GET /" — אל כתובת בענן של גוגל. 2️⃣ הפתק עבר את הדרך והגיע אל התוכנית שאתם כתבתם, שישבה וחיכתה בדיוק לרגע הזה. 3️⃣ נקודת הקצה שלכם זיהתה: "בקשת GET לכתובת /? זה שלי!". 4️⃣ השורה res.json(...) שלחה תשובה חזרה. 5️⃣ הדפדפן הציג אותה.

    ולמה זה גדול? כי זה — בדיוק זה — מה שקורה בכל לחיצה בכל אפליקציה שאתם מכירים. כשאתם פותחים וולט, בנק, אינסטגרם: דפדפן/אפליקציה שולחים בקשה ← שרת שמישהו כתב עונה ← המסך מתעדכן. ההבדל היחיד בין השורה שלכם לוולט: לוולט יש עוד כמה מאות נקודות קצה, ותשובות עשירות יותר. המנגנון — אחד לאחד מה שבניתם הרגע. אתם כבר בצד של מי שבונים את האינטרנט, לא רק גולשים בו.

    ומה זה הפורמט עם הסוגריים? JSON — פורמט התשובות הסטנדרטי של האינטרנט: זוגות של "שם":"ערך". תראו אותו בכל מקום מהיום.

// GET /api/summary → the budget, how much was spent, and the balance
app.get('/api/summary', async (req, res) => {
  const r = await pool.query('SELECT COALESCE(SUM(amount), 0) AS spent FROM expenses');
  const spent = Number(r.rows[0].spent);
  res.json({ budget: BUDGET, spent: spent, balance: BUDGET - spent });
});

// GET /api/expenses → the full list of expenses, newest first
app.get('/api/expenses', async (req, res) => {
  const r = await pool.query('SELECT * FROM expenses ORDER BY id DESC');
  res.json(r.rows);
});

// POST /api/expenses → add a new expense (sent from the form on the page)
app.post('/api/expenses', async (req, res) => {
  const description = req.body.description;
  const amount = req.body.amount;
  if (!description || !amount) {
    return res.status(400).json({ error: 'חסר תיאור או סכום' });
  }
  const r = await pool.query(
    'INSERT INTO expenses (description, amount) VALUES ($1, $2) RETURNING *',
    [description, amount]
  );
  res.status(201).json(r.rows[0]);
});

// DELETE /api/expenses/:id → delete one expense by its id number
app.delete('/api/expenses/:id', async (req, res) => {
  await pool.query('DELETE FROM expenses WHERE id = $1', [req.params.id]);
  res.json({ ok: true });
});

📚 שלושה מושגים בדקה, לפני הידיים

Git הוא כלי (שכבר מותקן לכם) ששומר "צילומי מצב" של תיקיית קוד — כל גרסה נשמרת, אפשר לחזור אחורה. GitHub הוא אתר שמאחסן עותקים של פרויקטים כאלה בענן — הספרייה העולמית של קוד. ריפו (Repository) = "תא" אחד בספרייה הזו, לפרויקט אחד.

ולמה אנחנו חייבים את זה עכשיו? סיבה מעשית אחת: Render — התחנה הבאה — לא יודע לקחת קוד מהטרמינל שלכם. הוא יודע לקחת קוד רק מריפו. GitHub הוא המסוע שמעביר את הקוד מהמחשב שלכם אל מכונת הפרסום. (עולם ה-Git עצום — branches, merges, עבודת צוות — ונקדיש לו הרצאה משלו. היום: המסלול המינימלי, המדויק, שעובד.)

  2. 🎯 שלב 5.2 · מציגים את עצמכם בפני Git (פעם אחת בחיים)

    מה הקטע: Git מסרב לשמור "צילום מצב" בלי לדעת מי המצלם. מגדירים שם ומייל — פעם אחת, והם נשמרים לתמיד בתיקיית הבית. שימו לב: זה המקום היחיד היום שבו מקלידים ערכים אישיים משלכם — החליפו את השם והמייל שבין הגרשיים:

    BASH · להדביק בטרמינל · להחליף את הערכים שבין הגרשיים
    # פעם אחת בלבד: מציגים את עצמכם בפני Git (השם יופיע ליד כל שמירה).
# החליפו את מה שבין הגרשיים בפרטים שלכם, באותיות באנגלית:
git config --global user.name "Israel Israeli"
git config --global user.email "israel@example.com"
# מבקשים מ-Git לזכור את פרטי ההתחברות, כדי להקליד אותם רק פעם אחת
git config --global credential.helper store
    🧠 מה זה אומר

    שתי השורות הראשונות = תג השם שלכם על כל שמירה. השלישית (credential.helper store) מבקשת מ-Git לזכור את פרטי ההתחברות ל-GitHub אחרי הפעם הראשונה — כדי שאת המפתח שניצור עוד רגע תדביקו פעם אחת בלבד. (הוא נשמר כקובץ טקסט בתיקיית הבית הפרטית שלכם — סבבה לסביבת לימוד.)

🤷 מה בדיוק Render עושה, ולמה GitHub לבד לא מספיק?

GitHub הוא ספרייה: שומר את הספר, לא מקריא אותו לאף אחד. כדי שהאתר יחיה, מישהו צריך להריץ את node server.js על מחשב שדולק תמיד, עם כתובת ציבורית. זה Render: הוא מתחבר לריפו, מתקין את הספריות, מריץ את השרת — ומחדש את הכל אוטומטית בכל פעם שתדחפו קוד חדש.

📛 ולמה לא GitHub Pages, שגם הוא חינמי?

GitHub Pages מגיש קבצים סטטיים בלבד — HTML/CSS/JS שנשלחים לדפדפן כמו-שהם. הוא לא מריץ שום תוכנית שרת. ל"תקציבי אביב" יש Backend אמיתי (server.js שמדבר עם Postgres) — ולכן חייבים שירות שמריץ תהליכים, כמו Render. אם תנסו Pages: תראו את קוד המקור כטקסט, לא אתר עובד.
