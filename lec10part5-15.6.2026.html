① לפני הכול

מה זה JSON?

כשאתה לוחץ "הזמן", פרטי ההזמנה נוסעים מהטלפון אל המחשב של החנות כ-JSON — דרך לכתוב נתונים כזוגות של תווית ותוכן, שכל מכשיר ובכל שפה יכולים לקרוא:

{

② פורמטים

JSON מול XML — ומה עוד קיים

אותו מידע בדיוק, בשתי שפות כתיבה. JSON משתמש בזוגות שדה-וערך; XML עוטף כל ערך בתגיות, כמו HTML:

JSON — זוגות שדה/ערך
{
  "item": "Burger",
  "price": 50
}
XML — תגיות
<order>
  <item>Burger</item>
  <price>50</price>
</order>
JSON: קליל, פחות מילולי, שולט ב-APIs מודרניים. XML: מילולי יותר, אבל תומך באימות מול סכמה (XSD) ובמבנים מורכבים — ולכן נפוץ במערכות ארגוניות ופיננסיות ותיקות.
לעולם הפיננסי: דיווח כספי לרגולטור (XBRL) ותקן התשלומים ISO 20022 — שניהם מבוססי XML.

וזה לא נגמר בשניים:

CSV — טבלאי, ייצוא מאקסל
YAML — קבצי הגדרות, קריא לאדם
Parquet — בינארי עמודתי, לנתוני ענק
Avro — בינארי, לצינורות נתונים
BigQuery קולט קבצים בכל הפורמטים האלה — JSON, CSV, Avro ו-Parquet — וטוען אותם לטבלאות.
🏷️ זהה כל קטע — באיזה פורמט הוא כתוב?

{ "item": "המבורגר", "price": 50, "city": "תל אביב" }

⑥ BigQuery · שליפה ☁️

שלוף שדות ופריטים מ-JSON

ב-BigQuery JSON_VALUE שולפת ערך לפי שם השדה — וגם מתוך רשימה לפי מיקום. נריץ שתי שאילתות, בלי שום טבלה.

  1. פתח את BigQuery Sandbox והתחבר עם חשבון Google.
  2. הרץ את שאילתה א' — שולפת שדה רגיל, וגם את שם הפריט הראשון והשני מהרשימה.
  3. הרץ את שאילתה ב' — שם השדה cost לא קיים. התוצאה null, בלי שום שגיאה.
א' · שליפת שדה + פריטים לפי מיקום
-- נותנים ל-JSON שם זמני (j) כדי לא לחזור עליו
WITH data AS (
  SELECT '{"order_id":88,"items":[{"name":"Burger","price":50},{"name":"Fries","price":20}]}' AS j
)
SELECT
  JSON_VALUE(j, '$.order_id')      AS order_id,
  JSON_VALUE(j, '$.items[0].name') AS first_item,
  JSON_VALUE(j, '$.items[1].name') AS second_item
FROM data;
ב' · שם שדה שגוי → null שקט
-- "cost" לא קיים. אין שגיאה — פשוט null.
SELECT
  JSON_VALUE('{"price":50}', '$.price') AS correct_name,
  JSON_VALUE('{"price":50}', '$.cost')  AS wrong_name;
💡 שאילתה א' שולפת מתוך רשימה לפי מיקום. שאילתה ב' מחזירה null שקט לשם שדה שגוי — בדיוק כך נשבר דשבורד שמחובר ל-API.

⑦ BigQuery · מרשימה לטבלה ☁️

UNNEST — לפתוח רשימת JSON לשורות, ולנתח

שליפה לפי מיקום טובה לפריט בודד. אבל כשרוצים את כל הפריטים, פותחים את הרשימה ל-שורה לכל פריט בעזרת UNNEST. וברגע שיש שורות — אפשר לסכם, למיין ולנתח, בדיוק כמו כל טבלה.

  1. הרץ את שאילתה ג' — פותחת את רשימת הפריטים לשורות. שתי שורות חוזרות:
תוצאה צפויה של ג':
item_nameitem_price
Burger50
Fries20
ג' · UNNEST — רשימה → שורות
-- JSON_QUERY_ARRAY מוציא את הרשימה, ו-UNNEST הופך אותה לשורות
WITH data AS (
  SELECT '{"order_id":88,"items":[{"name":"Burger","price":50},{"name":"Fries","price":20}]}' AS j
)
SELECT
  JSON_VALUE(item, '$.name')  AS item_name,
  JSON_VALUE(item, '$.price') AS item_price
FROM data, UNNEST(JSON_QUERY_ARRAY(j, '$.items')) AS item;
  1. הרץ את שאילתה ד' — עכשיו שיש שורות, מסכמים את סך ההזמנה (התוצאה: 70).
ד' · סך ההזמנה מתוך ה-JSON
-- סוכמים את מחירי כל הפריטים שפתחנו לשורות
WITH data AS (
  SELECT '{"order_id":88,"items":[{"name":"Burger","price":50},{"name":"Fries","price":20}]}' AS j
)
SELECT
  SUM(CAST(JSON_VALUE(item, '$.price') AS INT64)) AS order_total
FROM data, UNNEST(JSON_QUERY_ARRAY(j, '$.items')) AS item;
✅ זה סוגר את המעגל: JSON נכנס כבלוב מקונן, ו-UNNEST החזיר אותו לשורות ועמודות — טבלה רגילה שאפשר לסכם ולנתח. בדיוק החיבור בין מודול 1 (טבלאות) לעולם הנתונים שנכנסים.

סיימת — הסיפור בשורה אחת

  • JSON = נתונים כזוגות של שדה וערך · XML = אותו מידע בתגיות (נפוץ בפיננסים: XBRL, ISO 20022)
  • יש עוד פורמטים: CSV, YAML, Parquet, Avro — וכולם נטענים ל-BigQuery
  • JSON אמיתי מכיל רשימות ([ ]) ואובייקטים מקוננים
  • ב-BigQuery: JSON_VALUE שולף לפי שם/מיקום · שם שגוי = null שקט
  • UNNEST פותח רשימת JSON לשורות — ואז מסכמים ומנתחים כמו כל טבלה
