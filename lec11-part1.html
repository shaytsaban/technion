תחנה 1: איפה בדיוק קורה הקליק?

"הלקוח לוחץ הזמן" – אבל איפה? באתר? באפליקציה? ומה אם אין לקוח אנושי בכלל?

🌐 ארבעה מקומות שבהם "הקליק" יכול לקרות

רוב האנשים מדמיינים אתר בדפדפן. אבל במציאות, "הקליק" יכול להגיע מארבעה מקורות שונים – וכולם מדברים עם השרת באותה צורה בדיוק. זה מה שחשוב להבין.

🌐
אתר אינטרנט (Web App)

רץ בדפדפן – Chrome, Safari, Firefox, Edge. לא צריך התקנה.

  • דוגמאות אמיתיות: Amazon.com, eBay, KSP.co.il, כל חנות Shopify
  • טכנולוגיות נפוצות: React (של פייסבוק), Vue, Angular (של גוגל)
  • איך זה עובד: קוד JavaScript בדפדפן שולח בקשות HTTP לשרת
  • יתרון: נגיש מכל מכשיר עם דפדפן – מחשב, טאבלט, טלפון
  • חיסרון: דורש חיבור אינטרנט; בלי חיבור – האתר לא עובד
📱
אפליקציית מובייל

מותקנת בטלפון – iOS (אייפון) או Android (סמסונג, שיאומי וכו').

  • דוגמאות: Wolt, Spotify, Instagram, WhatsApp, אפליקציית בנק לאומי
  • טכנולוגיות: Swift (לאייפון), Kotlin (לאנדרואיד), React Native (לשניהם)
  • יתרון: גישה למצלמה, GPS, חיישנים, התראות push
  • יכולה לעבוד offline: שומרת בקשות ושולחת כשיש שוב חיבור
  • מבחינת השרת: מקבל בדיוק את אותה בקשת HTTP – אין הבדל!
🖥️
אפליקציית דסקטופ

מותקנת על המחשב – Windows, Mac, או Linux.

  • דוגמאות: Slack, Discord, Spotify Desktop, VS Code, Zoom
  • טכנולוגיות: Electron (כמו אתר אבל במחשב), .NET (מיקרוסופט), Java
  • יתרון: גישה למשאבי המחשב – קבצים, מערכת ההפעלה
  • מתאים ל: כלים מקצועיים, תוכנות פיתוח, אפליקציות כבדות
🤖
מערכת אחרת (API-to-API)

אין בן אדם מאחורי הקליק! שרת אחד מדבר עם שרת אחר.

  • דוגמה 1: מערכת המלאי שולחת הזמנה אוטומטית לספק כשהמלאי נמוך
  • דוגמה 2: Stripe (שירות תשלומים) שולח אישור תשלום לחנות שלכם
  • דוגמה 3: סקריפט לילי שמעתיק נתונים מהמסד התפעולי למחסן האנליטי
  • דוגמה 4: Google Analytics שולח דוח יומי למערכת הדיווח
  • עובדה מעניינת: רוב התעבורה באינטרנט היא machine-to-machine – לא בני אדם!

💡 התובנה הכי חשובה

מבחינת השרת – אין שום הבדל. הוא מקבל בקשת HTTP בין אם זה מדפדפן, מאפליקציה, או משרת אחר. לכן צוותי Backend בונים API אחד שמשמש את כל הלקוחות. זה חוסך זמן פיתוח, תחזוקה, וכסף.

🗺️ תרשים: כל הלקוחות מדברים עם אותו שרת

🏪 דוגמאות מהחיים האמיתיים

🛒 Wolt – אפליקציית מובייל

אתם פותחים את האפליקציה, בוחרים מנה, לוחצים "הזמן". האפליקציה שולחת JSON לשרת של Wolt. השרת שומר את ההזמנה במסד הנתונים, ושולח במקביל הודעה למסעדה.

🏦 בנק לאומי – גם אתר וגם אפליקציה

אותה העברה בנקאית יכולה להיעשות מהדפדפן בבית או מהאפליקציה בטלפון. הבק-אנד של הבנק מקבל בדיוק את אותה בקשת HTTP, ושומר באותו מסד נתונים. לכן היתרה מתעדכנת בשני המקומות.

🤖 הזמנה אוטומטית מספק

כשהמלאי של מוצר מסוים יורד מתחת לסף שהוגדר מראש, המערכת עצמה שולחת הזמנה לספק דרך API. אין כאן בן אדם שלוחץ – זה machine-to-machine. זה קורה אלפי פעמים ביום בחברות קמעונאיות.

בלוק 3 · הפרוטוקול · 45 דקות

תחנה 2: באיזו שפה הנתונים נשלחים?

מה זה ה-JSON הזה? מאיפה הוא בא? ולמה דווקא הוא?

📦 נתחיל מהשאלה: למה בכלל צריך "שפה"?

כשהלקוח לוחץ "הזמן", האפליקציה צריכה לשלוח לשרת את כל הפרטים: מי הלקוח, מה הוא קונה, כמה, לאן לשלוח. אבל איך היא "אורזת" את זה?

אי אפשר לשלוח סתם טקסט חופשי – השרת לא יבין. צריך פורמט מסודר שגם האפליקציה וגם השרת יודעים לקרוא ולכתוב. הפורמט הזה נקרא פרוטוקול.

📦 JSON – הפורמט השולט כיום

JSON (ראשי תיבות: JavaScript Object Notation) הוא פורמט טקסטואלי פשוט להעברת נתונים. הוא נראה כמו מילון – עם מפתחות (keys) וערכים (values).

🔍 בואו נראה דוגמה אמיתית

כשאתם לוחצים "הזמן" בחנות Mini-Shop, האפליקציה אורזת את כל ההזמנה ב-JSON שנראה בערך ככה:

{ "customer_id": 42, "customer_name": "יוסי כהן", "email": "yossi@example.com", "items": [ { "product_id": 7, "product_name": "חולצה כחולה", "quantity": 2, "price": 49.9 }, { "product_id": 15, "product_name": "ג'ינס שחור", "quantity": 1, "price": 149.0 } ], "shipping_address": "הרצל 1, תל אביב", "total": 248.8, "order_date": "2026-06-20T14:30:00Z" }

📖 איך קוראים את זה?

  • סוגריים מסולסלים { } – זה "אובייקט" (מילון של מפתחות וערכים)
  • סוגריים מרובעים [ ] – זו רשימה (array) של פריטים
  • "מפתח": ערך – כל שדה עם השם שלו. המפתח תמיד במרכאות
  • סוגי ערכים: מספר (42), מחרוזת ("יוסי"), רשימה, או אובייקט מקונן

💡 למה קוראים לזה "JavaScript Object Notation"?

JSON נולד במקור בתוך JavaScript – שפת התכנות של הדפדפן. אבל היום הוא עצמאי לחלוטין. כל שפת תכנות בעולם (Python, Java, C#, PHP, Go) יודעת לקרוא ולכתוב JSON. השם נשאר מסיבות היסטוריות, אבל JSON שייך לכולם.

🤔 מאיפה ה-JSON מגיע?

ה-JSON לא קיים לפני הלחיצה. הוא נוצר ברגע הלחיצה עצמה. בואו נראה איך:

1
🖱️ המשתמש לוחץ "הזמן"

הכפתור מפעיל פונקציית JavaScript בדפדפן

הפונקציה אוספת את כל הנתונים מהמסך: מה בעגלה, מי הלקוח (מה-cookie או מה-login), מה הכתובת למשלוח, איזה אמצעי תשלום נבחר.

2
📦 הקוד בונה אובייקט JavaScript

הנתונים מאורגנים במבנה היררכי בזיכרון הדפדפן

מפתח האתר כתב מראש קוד שאוסף את הנתונים למבנה מסודר. זה לא JSON עדיין – זה אובייקט JavaScript בזיכרון.

3
🔄 המרה לטקסט: JSON.stringify()

האובייקט הופך לטקסט שאפשר לשלוח באינטרנט

פונקציה מובנית ב-JavaScript בשם JSON.stringify() לוקחת את האובייקט והופכת אותו לטקסט JSON. עכשיו זה מוכן לשליחה.

4
📡 שליחה דרך HTTP לשרת

ה-JSON נשלח כ"גוף" של בקשת HTTP POST

הדפדפן שולח את הטקסט דרך האינטרנט לכתובת השרת. ה-JSON הוא ה"body" של הבקשה – התוכן עצמו.

5
📨 השרת מקבל ומפענח

השרת הופך את ה-JSON חזרה לאובייקט בזיכרון שלו

בצד של השרת, פונקציה כמו JSON.parse() (ב-JavaScript) או המקבילה שלה בשפת השרת, הופכת את הטקסט חזרה לאובייקט שאפשר לעבוד איתו.

⚖️ למה דווקא JSON? מה האלטרנטיבות?

פורמט איך נראה יתרונות חסרונות מתי משתמשים
JSON {"name":"יוסי"} קריא, קל, גמיש, נתמך בכל שפה אין validation מובנה 95% מה-APIs החדשים
XML <name>יוסי</name> מובנה, תומך ב-validation גדול, מסורבל, קשה לקריאה בנקים, ממשל, legacy
GraphQL שאילתה מובנית הלקוח בוחר מה לקבל מורכב יותר פייסבוק, GitHub
Protobuf בינארי (לא קריא) הכי קטן ומהיר לא קריא לבני אדם שירותים פנימיים של גוגל

🇮🇱 מה קורה בישראל?

90%+ מהחברות משתמשות ב-JSON כברירת מחדל – סטארטאפים, חברות הייטק, e-commerce.
XML עדיין נפוץ בבנקים (לאומי, הפועלים, דיסקונט), משרדי ממשלה, ומערכות בריאות (קופ"ח) – בעיקר בגלל מערכות legacy בנות 20+ שנה ודרישות רגולציה.

🤔 מי מחליט באיזה פורמט להשתמש?

ההחלטה מתקבלת בדרך כלל על ידי:

  • ארכיטקט התוכנה (Software Architect) – האדם שמחליט על המבנה הטכני של המערכת
  • ראש צוות Backend (Tech Lead) – מוביל הפיתוח של השרת
  • בסטארטאפים קטנים: המפתחים עצמם, לפעמים בהתייעצות עם CTO

ההחלטה מתקבלת בתחילת הפרויקט, ולרוב לא משתנה אחר-כך – כי להחליף פורמט בדיעבד אומר לשנות גם את השרת וגם את כל הלקוחות (האתר, האפליקציה, המערכות שמדברות איתו). זה יקר ומסוכן.

תחנה 3: השרת שמקבל את הבקשה

מה זה Node.js? Python? Java? איך זה קשור למשתמש? ולמה זה חשוב לי כאנליסט?

⚙️ מה זה "בק-אנד" בכלל?

בק-אנד (Backend) הוא השרת שמקבל את הבקשות מהפרונט-אנד (האתר/אפליקציה), מבצע את הלוגיקה העסקית, ושומר את הנתונים במסד הנתונים.

🎭 אנלוגיה: המסעדה

איך המסעדה עובדת – ואיך זה מקביל למערכת שלנו

  • הלקוח (יושב בשולחן) לא נכנס למטבח. הוא לא יודע איך מבשלים, ולא צריך לדעת.
  • המלצר (פרונט-אנד) לוקח את ההזמנה, מעביר אותה למטבח, ומחזיר את המנה המוכנה.
  • המטבח (בק-אנד) מבשל את המנה לפי המתכון. הוא זה שמחליט מה ואיך.
  • המחסן (מסד נתונים) שומר את כל חומרי הגלם – בשר, ירקות, תבלינים.

💻 באילו שפות כותבים בק-אנד?

השרת יכול להיכתב בכל שפת תכנות שתומכת ב-HTTP. אבל בפועל, ארבע שפות שולטות בשוק:

מי משתמש: Netflix, Uber, PayPal, LinkedIn, הרבה סטארטאפים ישראליים.
למה פופולרי: מפתח פרונט-אנד יכול לכתוב גם בק-אנד – אותה שפה. פיתוח מהיר.
מסגרות: Express.js, NestJS
🐍
Python

שפה פשוטה וקריאה. פופולרית גם ב-Web וגם ב-Data/AI.

Data + Web
מי משתמש: Instagram, Spotify, Dropbox, Pinterest, חברות AI.
למה פופולרי: תחביר נקי, המון ספריות מוכנות, השפה המובילה ב-Data Science.
מסגרות: Django, FastAPI, Flask
☕
Java

ותיקה, יציבה, מהירה. שולטת בארגונים גדולים.

ארגונים
מי משתמש: בנקים (לאומי, הפועלים), חברות ביטוח, Amazon, LinkedIn, Airbnb.
למה פופולרי: יציבות של עשרות שנים, ביצועים גבוהים, תמיכה ארוכת טווח.

Microsoft Stack

למה פופולרי: אינטגרציה מושלמת עם Azure, Active Directory, Office 365.
מסגרות: ASP.NET Core

🇮🇱 מה קורה בישראל?

סטארטאפים וחברות הייטק: Node.js ו-Python שולטים. למה? פיתוח מהיר, קהילה חזקה, קל לגייס מפתחים.
ארגונים גדולים (בנקים, ביטוח, ממשל): Java ו-C# שולטים. למה? יציבות, תמיכה ארוכת טווח, צוותים גדולים שעובדים על אותה קוד במשך עשרות שנים.

🔄 מה קורה כשהבק-אנד מקבל JSON?

כשהבק-אנד מקבל את ה-JSON, הוא צריך להפוך אותו למשהו שהוא יכול לעבוד איתו. בואו נראה את זה צעד-צעד.

🎬 שלב 1: פענוח JSON ל"אובייקטים פנימיים"

מה זה "אובייקט פנימי"? זה מבנה נתונים בזיכרון של התוכנית, שמאפשר לגשת לשדות בקלות. במקום לחפש בתוך טקסט איפה כתוב "customer_id", התוכנית פשוט כותבת order.customer_id ומקבלת 42.

📦 JSON (טקסט) → אובייקט בזיכרון

💡 למה זה חשוב?

טקסט הוא רק רצף תווים – אי אפשר "לחשב" איתו. כדי שהתוכנית תוכל לעשות משהו שימושי (למשל: לחשב סך הכל, לבדוק מלאי, להוסיף מס), היא חייבת להפוך את הטקסט למבנה שהיא מבינה. זה בדיוק מה ש-JSON.parse() עושה.

🎬 שלב 2: לוגיקה עסקית

עכשיו, כשהנתונים בזיכרון, הבק-אנד מבצע את כל הבדיקות והחישובים:

  • ✓ האם הלקוח קיים במערכת?
  • ✓ האם כל המוצרים במלאי?
  • ✓ האם המחירים נכונים? (לפעמים יש הנחות מיוחדות)
  • ✓ חישוב סך הכל + מס + משלוח
  • ✓ אישור תשלום מחברת האשראי
  • ✓ שמירת ההזמנה במסד הנתונים
בלוק 5 · השמירה · 45 דקות

תחנה 4: השמירה במסד הנתונים

מה זה INSERT INTO? איך הנתונים באמת נכנסים לטבלה?

🗺️ הסיפור המלא: מהבקשה לטבלאות

נחזור ל-Mini-Shop. יוסי הזמין 2 חולצות כחולות. הבק-אנד קיבל את ה-JSON, פענח אותו, בדק מלאי – ועכשיו הוא צריך לשמור את ההזמנה. אבל איפה בדיוק הוא שומר אותה?

התשובה: בכמה טבלאות מקושרות. בואו נכיר אותן:

👥 טבלת customers לקוחות
id (PK)nameemailcountry
42יוסי כהןyossi@example.comIsrael
📦 טבלת products מוצרים
id (PK)namecategorypricestock
7חולצה כחולהclothing49.915
🛒 טבלת orders הזמנות
id (PK)customer_id (FK)totalstatuscreated_at
12344299.8pending2026-06-20
📋 טבלת order_items פריטי הזמנה
id (PK)order_id (FK)product_id (FK)qtyprice
567812347249.9

💡 למה 4 טבלאות ולא אחת?

PK = Primary Key (מפתח ראשי, מזהה ייחודי). FK = Foreign Key (מפתח זר, מצביע לטבלה אחרת).
הנתונים מחולקים לטבלאות כדי לא לחזור על עצמם (נורמליזציה). שם הלקוח שמור פעם אחת ב-customers, לא בכל הזמנה. שם המוצר שמור פעם אחת ב-products. זה חוסך מקום ומונע טעויות.

📝 שלב 3: הבק-אנד בונה שאילתות SQL

עכשיו הבק-אנד צריך לכתוב את הנתונים לטבלאות. הוא משתמש בשפה שנקראת SQL (Structured Query Language). בואו נראה איך זה נראה עבור ההזמנה של יוסי:

🎯 שאילתה 1: יצירת ההזמנה עצמה

-- הוספת שורה חדשה לטבלת orders INSERT INTO orders (customer_id, total, status, created_at) VALUES (42, 99.8, 'pending', '2026-06-20 14:30:00'); -- קבלת המזהה של ההזמנה החדשה (auto-generated) SELECT LAST_INSERT_ID(); -- מחזיר: 1234

🎯 שאילתה 2: הוספת הפריטים להזמנה

-- הוספת פריט לטבלת order_items INSERT INTO order_items (order_id, product_id, qty, price) VALUES (1234, 7, 2, 49.9);

🎯 שאילתה 3: עדכון המלאי

-- הפחתת הכמות מהמלאי UPDATE products SET stock = stock - 2 WHERE id = 7;

⚠️ שימו לב – זה לא פשוט!

צריך לבצע 3 פעולות נפרדות על 2 טבלאות שונות. מה קורה אם הפעולה הראשונה הצליחה (ההזמנה נשמרה), אבל השלישית נכשלה (המלאי לא עודכן)? המערכת במצב לא עקבי – יש הזמנה אבל המלאי לא ירד. על זה בדיוק פותרת הטרנזקציה, שנכיר בבלוק הבא.

🔌 שלב 4: איך הבק-אנד "מדבר" עם מסד הנתונים?

הבק-אנד (שכתוב ב-Python/Java/Node.js) לא יכול פשוט "לדבר" ישירות עם מסד הנתונים. הוא צריך מתרגם. יש שתי דרכים עיקריות:

🛠️ דרך 1: Driver (דרייבר)

דרייבר הוא ספריית תוכנה קטנה שיודעת "לדבר" עם מסד נתונים ספציפי. לדוגמה:

  • pg – דרייבר ל-PostgreSQL ב-Node.js
  • psycopg2 – דרייבר ל-PostgreSQL ב-Python
  • mysql2 – דרייבר ל-MySQL ב-Node.js
  • JDBC – דרייבר כללי ל-Java שעובד עם כל מסד

הדרייבר פותח חיבור רשת למסד הנתונים (בדרך כלל בפרוטוקול TCP), שולח את ה-SQL, ומחזיר את התוצאה.

// דוגמה: שמירת הזמנה עם דרייבר pg const { Pool } = require('pg'); const pool = new Pool({ connectionString: process.env.DATABASE_URL }); // שליחת פקודת SQL למסד הנתונים const result = await pool.query( "INSERT INTO orders (customer_id, total) VALUES ($1, $2) RETURNING id", [order.customer_id, order.total] ); console.log("נוצרה הזמנה מספר:", result.rows[0].id);

🛠️ דרך 2: ORM (Object-Relational Mapping)

ORM הוא שכבה נוספת מעל הדרייבר. הוא מאפשר לעבוד עם טבלאות כאילו הן אובייקטים בשפת התכנות – בלי לכתוב SQL ידנית.

// אותה פעולה, אבל עם ORM – בלי SQL! const newOrder = await prisma.order.create({ data: { customer_id: order.customer_id, total: order.total, status: 'pending' } }); console.log("נוצרה הזמנה מספר:", newOrder.id);
גישת השוואה Driver (דרייבר) ORM
כתיבת SQL ידנית – אתה כותב את ה-SQL אוטומטית – ה-ORM מייצר SQL
שליטה מלאה – אפשר לכתוב כל שאילתה מוגבלת – ה-ORM מחליט
ביצועים מהירים יותר (SQL מותאם) קצת יותר איטיים
נוחות דורש ידע ב-SQL נוח מאוד למפתחים
דוגמאות pg, psycopg2, mysql2 Prisma, Sequelize, TypeORM, SQLAlchemy

🇮🇱 מה נפוץ בישראל?

סטארטאפים: בדרך כלל ORM (Prisma, Sequelize) – פיתוח מהיר.
ארגונים גדולים: לרוב דרייבר ישיר או ORM כבד (Hibernate ב-Java) – שליטה מלאה וביצועים.

בלוק 6 · מסד תפעולי · 60 דקות

מה זה "מסד נתונים תפעולי"?

איפה הנתונים באמת יושבים? אילו מסדים קיימים? מי משתמש במה?

🗄️ הגדרה: מה זה מסד נתונים תפעולי?

מסד נתונים תפעולי (נקרא גם OLTP – Online Transaction Processing) הוא המקום שבו העסק חי ונושם בזמן אמת. כל הזמנה, כל לקוח, כל מוצר – הכל שמור כאן.

🎯 מה התפקיד שלו?

  • לקבל הזמנות מלקוחות עכשיו
  • לעדכן מלאי בזמן אמת
  • לשמור כל פעולה באופן אמין – גם אם נופל החשמל
  • לאפשר לאלפי משתמשים לעבוד בו-זמנית בלי להפריע אחד לשני

⚡ שלוש דרישות קריטיות

1. מהירות: כל פעולה חייבת להסתיים באלפיות שנייה – כי הלקוח ממתין לתשובה.
2. אמינות: אסור לאבד אף הזמנה – גם אם יש הפסקת חשמל או תקלה בשרת.
3. מקביליות: אלפי לקוחות קונים בו-זמנית, והמערכת חייבת להתמודד בלי "לדרוס" נתונים של אחרים.

📊 אילו מסדי נתונים תפעוליים קיימים?

המסדים מתחלקים לשתי משפחות עיקריות: SQL (טבלאות) ו-NoSQL (גמישים). בואו נכיר את הנפוצים:

בלוק 7 · טרנזקציה · 45 דקות

תחנה 5: טרנזקציה – הכל או כלום

מה קורה אם חצי מהשמירה הצליחה וחצי נכשלה?

🔥 הבעיה: "חצי הזמנה"

נחזור לדוגמה של יוסי. כדי להשלים את ההזמנה שלו, הבק-אנד צריך לבצע 3 פעולות נפרדות:

1
יצירת ההזמנה ב-orders

INSERT לטבלת ההזמנות

2
הוספת הפריטים ב-order_items

INSERT לטבלת פריטי הזמנה

3
עדכון המלאי ב-products

UPDATE שמפחית את הכמות מהמלאי

😱 מה קורה אם פעולה 1 הצליחה אבל 3 נכשלה?

התוצאה: יש הזמנה במערכת, אבל המלאי לא ירד. זה אומר:

  • הלקוח חויב על מוצר שאולי אין במלאי
  • לקוח אחר עלול להזמין את אותו מוצר במקביל – ואז שניהם יתאכזבו
  • הדוחות של המנהל יהיו שגויים

💡 הפתרון: טרנזקציה

טרנזקציה היא קבוצה של פעולות שמתבצעות כיחידה אחת. או שהכל מצליח – או שהכל מתבטל. אין אמצע.

🔄 איך טרנזקציה עובדת?

שלוש פקודות SQL מיוחדות שולטות בטרנזקציה:

-- שלב 1: מתחילים טרנזקציה BEGIN TRANSACTION; -- שלב 2: מבצעים את כל הפעולות INSERT INTO orders (customer_id, total, status) VALUES (42, 99.8, 'pending'); INSERT INTO order_items (order_id, product_id, qty, price) VALUES (1234, 7, 2, 49.9); UPDATE products SET stock = stock - 2 WHERE id = 7; -- שלב 3: אם הכל הצליח – COMMIT (שמור לצמיתות) -- אם משהו נכשל – ROLLBACK (בטל הכל) COMMIT; -- או ROLLBACK

📋 תרחישים אפשריים

✅
תרחיש 1: הכל מצליח

כל 3 הפעולות בוצעו בהצלחה → COMMIT

  • ההזמנה נשמרה
  • הפריטים נשמרו
  • המלאי עודכן
  • הלקוח מקבל אישור
❌
תרחיש 2: משהו נכשל

למשל: המלאי אזל → ROLLBACK

  • ההזמנה מתבטלת
  • הפריטים מתבטלים
  • המלאי חוזר לקדמותו
  • הלקוח מקבל "אזל מהמלאי"

🛡️ מי מגדיר את הטרנזקציה?

💡 המפתח מגדיר – לא המשתמש

המשתמש (יוסי) לא יודע ולא צריך לדעת שיש טרנזקציה. מפתח הבק-אנד הוא זה שמגדיר בקוד: "כל הפעולות האלה הן טרנזקציה אחת".

ברגע שהמפתח הגדיר את זה – מסד הנתונים עצמו אחראי לוודא שהכל או כלום. זה מנגנון מובנה במסד, לא משהו שהמפתח צריך לממש בעצמו.

🎬 דוגמה בקוד אמיתי (Node.js)

const client = await pool.connect(); try { // מתחילים טרנזקציה await client.query('BEGIN'); // פעולה 1: יצירת הזמנה const orderResult = await client.query( "INSERT INTO orders (customer_id, total) VALUES ($1, $2) RETURNING id", [42, 99.8] ); const orderId = orderResult.rows[0].id; // פעולה 2: הוספת פריטים await client.query( "INSERT INTO order_items (order_id, product_id, qty) VALUES ($1, $2, $3)", [orderId, 7, 2] ); // פעולה 3: עדכון מלאי await client.query( "UPDATE products SET stock = stock - $1 WHERE id = $2 AND stock >= $1", [2, 7] ); // אם הגענו לכאן – הכל הצליח! await client.query('COMMIT'); console.log('✅ ההזמנה נשמרה בהצלחה'); } catch (error) { // משהו נכשל – מבטלים הכל! await client.query('ROLLBACK'); console.log('❌ ההזמנה בוטלה:', error.message); } finally { client.release(); }

🎓 ACID – ארבעת עמודי התווך של טרנזקציות

טרנזקציה תקפה חייבת לעמוד בארבע דרישות, שמכונות ACID:

🎯
A – Atomicity (אטומיות)

"הכל או כלום" – אין מצב של חצי הצלחה.

  • או שכל הפעולות בטרנזקציה מצליחות
  • או שאף אחת מהן לא קורית
  • כמו אטום – לא ניתן לחלק
⚖️
C – Consistency (עקביות)

הנתונים נשארים הגיוניים אחרי הטרנזקציה.

  • המלאי לא יורד מתחת לאפס
  • סכומי כסף תואמים בין טבלאות
  • כל החוקים העסקיים נשמרים
🔒
I – Isolation (בידוד)

טרנזקציות מקבילות לא מפריעות זו לזו.

  • שני לקוחות שקונים בו-זמנית – כל אחד רואה מלאי "נכון"
  • אין "קריאות מלוכלכות" של נתונים לא גמורים
  • נשמר סדר הגיוני
💾
D – Durability (עמידות)

אחרי COMMIT – הנתונים נשמרים לצמיתות.

  • גם אם נופל החשמל מיד אחרי
  • גם אם השרת קורס
  • הנתונים נשמרים בדיסק

💡 למה זה חשוב לאנליסט?

כשתנתחו נתונים במחסן האנליטי (בהמשך הקורס), אתם יכולים לסמוך שהנתונים שאתם רואים הם עקביים ואמיתיים. זאת בגלל שמסד הנתונים התפעולי הקפיד על ACID כשהנתונים נשמרו. בלי ACID – הנתונים היו מלאי סתירות.

בלוק 8 · מיקום · 60 דקות

איפה מסד הנתונים פיזית נמצא?

On-Premises מול Cloud – AWS, Azure, GCP – מה ההבדלים?

🏠 מול ☁️ – שתי אפשרויות עיקריות

🏠
On-Premises (בבית)

החברה קונה שרתים פיזיים ומציבה אותם אצלה.

  • שליטה מלאה בחומרה וברשת
  • מתאים לרגולציה מחמירה – הנתונים לא יוצאים מהחברה
  • יקר מאוד: מאות אלפי ₪ לשרתים, חדר מאובטח, מיזוג, UPS
  • דורש צוות: DBA, אנשי IT, אנשי רשת
  • קשה לגדול: צריך לקנות עוד שרתים פיזית
  • מי משתמש: בנקים (בגלל רגולציית בנק ישראל), משרדי ממשלה, צה"ל, חברות ביטוח ותיקות
☁️
Cloud (בענן)

שוכרים מסד נתונים מנוהל מספק ענן.

  • זול להתחלה: משלמים לפי שימוש
  • אין צוות DBA: הספק מתחזק הכל
  • Auto-scaling: המסד גדל אוטומטית עם העומס
  • גיבויים מובנים: snapshots, disaster recovery
  • חיסרון: עלויות יכולות לצמוח, תלויים בספק
  • מי משתמש: 80%+ מהחברות החדשות

🔀 גישה שלישית: היברידית

הרבה ארגונים גדולים עובדים גם וגם: נתונים רגישים (תעודות זהות, יתרות בנק) נשארים on-premises, בעוד אפליקציות חדשות וניתוחים עוברים לענן.

☁️ שלושת ספקי הענן הגדולים

שלוש חברות שולטות בשוק הענן העולמי – AWS, Azure, ו-Google Cloud. בואו נכיר אותן לעומק:

🟧 AWS (Amazon Web Services)

מוביל השוק העולמי. של אמזון. הוותיק והגדול ביותר.

  • נתח שוק עולמי: כ-32% (הכי גדול)
  • מסד נתונים SQL עיקרי: Amazon RDS (PostgreSQL, MySQL, SQL Server, Oracle)
  • מסד מתקדם: Amazon Aurora – מהיר פי 5 מ-PostgreSQL רגיל
  • מחסן אנליטי: Amazon Redshift
  • NoSQL: DynamoDB
  • יתרון: הכי הרבה שירותים (200+), הכי הרבה דוקומנטציה
  • חיסרון: מורכב ללמידה, ממשק ניהול מיושן
בעולם: Netflix, Airbnb, Lyft, NASA, Samsung, McDonald's
בישראל: סטארטאפים רבים (Wix חלקית, Monday, Fiverr), חברות סייבר, e-commerce

🔹 Microsoft Azure

של מיקרוסופט. דומיננטי בארגונים. אינטגרציה מלאה עם Office ו-Active Directory.

  • נתח שוק עולמי: כ-23% (שני)
  • מסד SQL עיקרי: Azure SQL Database (SQL Server מנוהל)
  • מסד מתקדם: Azure SQL Managed Instance
  • מחסן אנליטי: Azure Synapse Analytics
  • NoSQL: Cosmos DB
  • יתרון: 95% מ-Fortune 500 כבר לקוחות מיקרוסופט – מעבר קל
  • יתרון: אינטגרציה מושלמת עם Power BI, Office 365, Teams
  • חיסרון: פחות מתאים לסטארטאפים שמעדיפים כלים open-source
בעולם: 95% מ-Fortune 500, BMW, Boeing, Pfizer
בישראל: בנקים (לאומי, הפועלים, דיסקונט), חברות ביטוח (הפניקס, כלל), משרדי ממשלה, צה"ל

🔷 Google Cloud (GCP)

של גוגל. חזק ב-Data, AI ו-Kubernetes. הכי חדשני.

  • נתח שוק עולמי: כ-11% (שלישי, אבל צומח מהר)
  • מסד SQL עיקרי: Cloud SQL (PostgreSQL, MySQL)
  • מסד מתקדם: Cloud Spanner – מסד גלובלי מבוזר
  • מחסן אנליטי: BigQuery – הכוכב של הקורס שלנו!
  • NoSQL: Firestore (לאפליקציות מובייל)
  • יתרון: BigQuery הוא כנראה מחסן הנתונים הטוב בעולם כיום
  • יתרון: הכי חזק ב-AI/ML (Vertex AI), Kubernetes (הומצא בגוגל)
  • חיסרון: פחות שירותים מ-AWS, פחות דומיננטי בארגונים
בעולם: Spotify, PayPal, HSBC, Shopify, Twitter
בישראל: חברות הייטק שמתמקדות ב-Data (Wix, Taboola), סטארטאפים של AI

🇮🇱 מה קורה בישראל?

Azure מוביל בארגונים הגדולים – בנקים, חברות ביטוח, ממשל. הסיבה: הקשר ההיסטורי עם מיקרוסופט, Active Directory, Office 365, Power BI.
AWS מוביל בסטארטאפים ובחברות הייטק – הכי הרבה שירותים, הכי הרבה קהילה.
Google Cloud צומח מהר – בעיקר בחברות שמתמקדות ב-Data ו-AI, בזכות BigQuery.

כל שלושת הספקים פתחו חוות שרתים פיזיות בישראל בשנים האחרונות (2021-2023), מה שמאפשר לחברות ישראליות לאחסן נתונים בתוך הארץ – חשוב לרגולציה.

מה למדנו עד כאן?

סיכום חמש התחנות הראשונות במסע הנתונים

🗺️ חמש התחנות של חלק א׳

1
🖱️ הקליק

קורה באתר, אפליקציה, דסקטופ, או API-to-API. מבחינת השרת – אין הבדל. כולם שולחים HTTP.

2
📨 JSON

הפורמט שבו הנתונים נארזים. טקסט פשוט של מפתחות וערכים. נוצר ברגע הלחיצה, נשלח לשרת.

3
⚙️ הבק-אנד

השרת שמקבל את הבקשה. כתוב ב-Node.js, Python, Java, או C#. מבצע לוגיקה עסקית ושומר במסד.

4
📝 INSERT INTO

שאילתת SQL שמוסיפה שורה לטבלה. הנתונים מחולקים לכמה טבלאות מקושרות (orders, order_items, ...).

5
💾 מסד הנתונים התפעולי

PostgreSQL, SQL Server, MySQL, Oracle. יושב on-premises או בענן (AWS, Azure, GCP). שומר בטרנזקציה (ACID).

🎯 השורה התחתונה של חלק א׳

כשלקוח לוחץ "הזמן", הנתונים עוברים מסע של חמש תחנות: מהקליק באפליקציה, דרך JSON לשרת הבק-אנד, דרך INSERT INTO לטבלאות, ולבסוף נשמרים במסד הנתונים התפעולי – בטרנזקציה שמבטיחה הכל או כלום.
