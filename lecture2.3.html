לוגיקה עסקית וזמן
במסד הנתונים

עד עכשיו פשוט שלפנו מידע קיים. בפרק הזה אנחנו הולכים לייצר מידע חדש תוך כדי שליפה. נלמד איך להתמודד עם "חורים" בנתונים, איך לסווג נתונים אוטומטית בעזרת תנאים, ואיך לנסוע בזמן.

האויב השקוף: התמודדות עם ריק

דמיינו שאתם מנתחי הנתונים של חברת TechCorp. המנכ"ל מבקש לדעת מהי העלות הכוללת של כל עובד. העלות מורכבת מחיבור של שתי עמודות:

salary + budget

אבל יש בעיה. לא כל העובדים קיבלו עדיין "תקציב אושר" (Budget). לחלקם פשוט אין נתון בטבלה. במסדי נתונים, מצב של "אין נתון" נקרא:

NULL

שלב 1: Visual First - להבין את הבעיה

הביטו בטבלאות למטה (צד מול צד). בטבלה הימנית יש לנו את הנתונים הגולמיים. בטבלה השמאלית, ניסינו לעשות חיבור מתמטי פשוט. ראו מה קרה לרונית!

הנתונים הגולמיים

namesalarybudget

Ronit12,000NULL

התוצאה השבורה

nameTotal Cost (salary + budget)

למה זה קרה? כלל ברזל מתמטי:
כל מספר ועוד ריק, שווה תמיד ריק! המחשב אומר: "אני לא יכול לחבר 12,000 עם משהו שאני לא יודע מהו". בגלל זה, המשכורת של רונית נמחקה מהדוח לחלוטין!

שלב 2: הפתרון

אנחנו צריכים להגיד למחשב: "אם אתה רואה מצב ריק, תתייחס אליו כאל אפס (0)". לשם כך נשתמש בפונקציה מיוחדת:

COALESCE(budget, 0)

פירוק התחביר:

COALESCE - "קח את הערך הראשון שלא ריק".
(budget, 0) - "קודם כל, נסה לקחת את העמודה. אם יש בה מספר, קח אותו. אם יש בה ריק, תדלג ותיקח את המספר 0 במקום".

סימולטור 1: תיקון הדוח

הקוד שלפניכם שבור. הוא מנסה לחבר את השכר והתקציב באופן ישיר.
המשימה שלכם: עטפו את המילה budget בפונקציה שלמדנו, והריצו שוב כדי להציל את הדוח!

💡 נתקעתם? לחצו כאן לרמז מפורט ▼

כדי לפתור את התרגיל, עליכם להחליף את המילה הבודדת בתחביר הפונקציה המלא.

במקום לכתוב:

salary + budget

עליכם לכתוב:

salary + COALESCE(budget, 0)

הדבר יבטיח שאם התקציב חסר, המחשב יחבר את השכר עם אפס במקום לקרוס.

סיווג אוטומטי: תנאים חכמים

המנכ"ל ראה את הדוח ואמר: "מספרים זה יפה, אבל אני צריך לדעת מיד מי בסיכון לעזוב את החברה!".

בטבלה שלנו יש עמודה של ציון אושר הנקראת:

happiness_score

אנחנו רוצים לייצר עמודה חדשה שתקרא את הציון ותסווג אותו למילים ברורות: "בסיכון" או "בטוח". לשם כך משתמשים בכלי החזק ביותר ב-SQL ליצירת לוגיקה:

CASE WHEN

שלב 1: Visual First - המטרה

הביטו כיצד ציון מספרי הופך לטקסט עסקי ברור בזמן אמת (הטבלה הימנית היא הענן, השמאלית היא התוצאה באפליקציה):

הענן (Raw)

namehappiness_score
Dan8
Sarah4

האפליקציה (View)

nameRisk Status
DanSafe
SarahHigh Risk

שלב 2: פירוק התחביר

ככה כותבים את הפקודה הזו בתוך החלק של הבחירה:

CASE
  WHEN happiness_score < 5 THEN 'High Risk'
  ELSE 'Safe'
END AS Risk_Status
CASE - "מחשב יקר, אני פותח כאן קופסה של תנאים."
WHEN ... THEN - "כאשר הציון קטן מ-5, אז תדפיס בעמודה 'High Risk'."
ELSE - "אחרת (בכל שאר המקרים), תדפיס 'Safe'."
END - "סיימתי את התנאים, סגור קופסה."
AS - "קרא לעמודה החדשה שיצרנו בשם זה."

סימולטור 2: בוני הלוגיקה

המשימה שלכם: הוסיפו את בלוק התנאים שלמדנו כדי לסווג את העובדים לפי הציון שלהם. קראו לעמודה status.

💡 טיפ מהארכיטקט: איך לכתוב את הבלוק ▼

1. ודאו שיש פסיק אחרי המילה happiness_score כדי להפריד בין העמודות.

2. התחילו עם המילה CASE.

3. הגדירו את התנאי: WHEN happiness_score < 5 THEN 'High Risk'

4. הגדירו את הברירת מחדל: ELSE 'Safe'

5. סיימו עם: END AS status

מסע בזמן (תאריכים)

בעולם האמיתי, הנתונים הם לעולם לא סטטיים. מנהל לא שואל "כמה הוצאנו אי פעם?", הוא שואל "כמה הוצאנו בשנת 2026?".

במסדי נתונים, הסטנדרט הבינלאומי לשמירת תאריך הוא תמיד משמאל לימין: שנה, חודש, יום. לדוגמה:

'2026-05-14'

איך מסננים?

מכיוון שהמחשב שומר את התאריך במבנה אחיד מגדול (שנה) לקטן, אנחנו יכולים להשתמש בסימנים מתמטיים כמו "גדול מ..." או "קטן מ..." כדי לנסוע בזמן בחלק של הסינון (WHERE).

דוגמאות:

WHERE hire_date >= '2026-01-01'

תביא לי רק עובדים שהתחילו לעבוד מ-1 בינואר 2026 והלאה.

WHERE hire_date < '2025-01-01'

תביא לי עובדים שהתחילו לפני שנת 2025.

סימולטור 3: מסנני זמן

הדוח למטה אמור להציג רק את העובדים החדשים.
המשימה שלכם: הוסיפו את המילה WHERE וסננו את עמודת התאריך כך שנקבל רק עובדים משנת 2026 והלאה.

💡 הסתבכתם עם התאריכים? הנה עזרה ▼

1. כיתבו בשורה האחרונה (אחרי שם הטבלה) את מילת הסינון WHERE.

2. ציינו את שם העמודה אותה אנו מסננים: hire_date.

3. השתמשו באופרטור "גדול או שווה" (>=) כדי לכלול את היום הראשון של השנה.

4. אל תשכחו לעטוף את התאריך במירכאות בודדות! '2026-01-01'

מבחן הארכיטקט המסכם

דרישת המערכת השלמה

מנהלת משאבי אנוש זקוקה לדוח מסכם וביקשה:
"אני צריכה דוח על כל העובדים שגויסו בשנת 2026. אני רוצה לדעת את שמם, את העלות האמיתית שלהם (שכר בתוספת תקציב, גם אם אין להם), ואת סיווג הסיכון שלהם (בסיכון או בטוחים)."

הידע הנדרש מכם:

  1. שליפת שם.
  2. שימוש בתיקון הריקים (COALESCE) לעלות הכוללת.
  3. שימוש בבלוק הלוגיקה (CASE) לסיווג.
  4. סינון תאריכים (WHERE).
💡 איך מחברים הכל ביחד? (מדריך צעד-אחר-צעד) ▼

האתגר משלב את כל מה שלמדנו. בנו את השאילתה בשלבים:

שלב 1: בחרו את השם והשתמשו בפונקציה מהפרק הראשון. קראו לה בשם שביקשו:

name, COALESCE(budget, 0) + salary AS total_cost,

שלב 2: מיד אחרי הפסיק, פתחו את קופסת הלוגיקה:

CASE WHEN happiness_score < 5 THEN 'High Risk' ELSE 'Safe' END AS risk_status

שלב 3: אחרי שסיימתם את הבחירה (SELECT) ואת הגדרת המקור (FROM), הוסיפו את הסינון בתחתית:

WHERE hire_date >= '2026-01-01'

אל תחששו לטעות, המערכת תגיד לכם בדיוק איפה הבעיה.
