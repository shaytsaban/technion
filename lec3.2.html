היכן אנחנו — מה עשינו ומה הולך לקרות

5 דקות

מפת ההתקדמות

בקובץ 1 בנינו את כל הבסיס התיאורטי: הבנו מה GAS, מה API, קיבלנו מפתח Alpha Vantage, ולמדנו CAPM, Beta ו-Sharpe Ratio.

בקובץ זה — נבנה את הלב של המערכת: הסקריפט שרץ על שרתי Google, שואב נתונים מ-3 מקורות (Yahoo → Alpha Vantage → Google Finance), מחשב CAPM, ומחזיר JSON/CSV לכל מי שפונה אל ה-URL שלו.

רשימת תיוג — לפני שמתחילים
  • ✅ קראתם את קובץ 1 (תיאוריה + CAPM)
  • ✅ יש לכם מפתח Alpha Vantage (מ-alphavantage.co)
  • ✅ יש לכם חשבון Google פעיל
  • ✅ פתוח דפדפן מוכן עם script.google.com
למה פרומפט אחד לסקריפט ואחד לממשק?
חלוקה לשני פרומפטים נפרדים מונעת "בלבול" של ה-AI: כשהוא מתמקד רק ב-Backend, הקוד שמייצא מדויק יותר, ללא ניסיון לשלב CSS ו-JavaScript ממשקי באותו פלט. כל פרומפט = תפקיד אחד = פלט נקי יותר.

לחצו "+ New project"כפתור כחול בצד שמאל למעלה. ייפתח עורך קוד עם קובץ ריק בשם Code.gs.
3
שנו את שם הפרויקטלחצו על "Untitled project" בפינה השמאלית עליונה. כתבו: Business Intelligence Script ← Enter.

מחקו את תוכן ה-Editorבחרו הכל (Ctrl+A) ולחצו Delete. הקובץ צריך להיות ריק לחלוטין לפני ההדבקה.
5
✅ הסביבה מוכנהעורך ריק + שם פרויקט = מוכנים לקבל את הקוד שה-AI ייצור בשלב הבא.

הפרומפט לסקריפט ה-GAS — העתיקו בדיוק

15 דקות

כללי שימוש בפרומפט

כלל ברזל — העתקה מלאה בלי שינויים
הפרומפט כולל מגבלות ("constraints") שמונעות מה-AI לסטות. כל מילה שתוסיפו, תגרעו, או תשנו — עלולה לגרום לסקריפט שגוי שייקח שעות לתקן. העתיקו Copy-Paste כפי שהוא.
לפני ההעתקה — החליפו את ה-API Key
בפרומפט יש placeholder: YOUR_ALPHA_VANTAGE_KEY. החליפו אותו במפתח שקיבלתם מ-Alpha Vantage (קובץ 1, סעיף 5) לפני שתדביקו ל-AI.

הפרומפט המלא — Prompt לסקריפט GAS בלבד

// ════════ הדביקו את הפרומפט הזה ל-Claude / ChatGPT / Gemini ════════ You are a senior backend engineer specializing in Google Apps Script. // === TASK === Create a complete, production-ready Google Apps Script (.gs file) that acts as a standalone Web App API for stock analysis. Do NOT generate any HTML or CSS. Output ONLY the .gs code, nothing else — no explanations, no markdown, no comments outside the code itself. // === FILE NAME === The output represents: "Business Intelligence Script.gs" // === API DESIGN === Expose a doGet(e) function as the single entry point. Read query parameters from e.parameter: - symbol (string, required): stock ticker, e.g. "AAPL" - action (string, optional): "analyze" (default) | "csv" | "health" - nocache (string, optional): "1" to bypass cache // === DATA SOURCES — 3-TIER FALLBACK (attempt in order) === TIER 1 — Yahoo Finance (no key required): URL: https://query1.finance.yahoo.com/v8/finance/chart/{SYMBOL}?interval=1d&range=4mo Parse: timestamps, close prices, volumes. TIER 2 — Alpha Vantage (free key): var AV_KEY = 'YOUR_ALPHA_VANTAGE_KEY'; URL: https://www.alphavantage.co/query?function=TIME_SERIES_DAILY&symbol={SYMBOL}&outputsize=compact&apikey={AV_KEY} Fallback also to TIME_SERIES_DAILY_ADJUSTED if DAILY fails on free tier. TIER 3 — Google Finance via UrlFetch: URL: https://query1.finance.yahoo.com/v7/finance/quote?symbols={SYMBOL} (Use only for current price + change% if tiers 1-2 fail for history) If all 3 tiers fail, return JSON: { "error": true, "message": "כל מקורות הנתונים אינם זמינים. אנא נסו שוב." } // === CALCULATIONS (perform server-side) === From the last 60 trading days of close prices + SPY prices (fetch SPY same way): 1. Beta = Covariance(stock_returns, spy_returns) / Variance(spy_returns) 2. SMA20 = average of last 20 close prices 3. annualized_return = ((last_price / price_60d_ago) ^ (252/60)) - 1 4. daily_std = standard deviation of daily_returns (last 60d) 5. annualized_std = daily_std * sqrt(252) 6. RF = 0.0425 (risk-free rate) 7. MARKET_RETURN = 0.10 8. capm_expected = RF + Beta * (MARKET_RETURN - RF) 9. alpha = annualized_return - capm_expected 10. sharpe = (annualized_return - RF) / annualized_std 11. signal: if alpha > 0.02 AND sharpe > 0.5 → "BUY" elif alpha < -0.02 → "SELL" else → "HOLD" // === RESPONSE FORMAT — action=analyze === Return ContentService JSON with this exact structure: { "symbol": "AAPL", "currentPrice": 189.3, "change_pct": 0.85, "sma20": 185.2, "beta": 1.24, "annualized_return": 0.18, "annualized_std": 0.22, "capm_expected": 0.1139, "alpha": 0.0661, "sharpe": 0.62, "signal": "BUY", "signal_reason": "Alpha חיובי של 6.6% מעל ציפיות CAPM. Sharpe Ratio חיובי.", "history": [ { "date": "2024-01-02", "close": 185.1, "volume": 55000000 } ], "source": "yahoo", "cached": false } // === RESPONSE FORMAT — action=csv === Return ContentService text/csv: Date,Close,Volume,Daily_Return 2024-01-02,185.1,55000000,0.0032 ... // === RESPONSE FORMAT — action=health === Return JSON: { "status": "ok", "timestamp": "...", "version": "2.0" } // === TECHNICAL REQUIREMENTS === 1. CacheService.getScriptCache() with key "v2_{symbol}_{action}", TTL 3600 seconds. 2. Skip cache when nocache=1. 3. All ContentService responses must set Access-Control-Allow-Origin: * via ContentService.createTextOutput(json).setMimeType(ContentService.MimeType.JSON) (Note: GAS does not support setHeader on TextOutput — do not attempt it) 4. Wrap ALL external UrlFetch calls in try/catch. Log errors with console.error(). 5. signal_reason must be a short Hebrew string explaining the signal. 6. Use only built-in GAS services: UrlFetch, CacheService, JSON, Math, console. Do NOT use SpreadsheetApp or any Sheets-related service. 7. SPY data fetch uses the same 3-tier logic as the target symbol. 8. If Beta calculation fails (insufficient data), use Beta = 1.0 as default.

אנטומיה של הפרומפט — למה כל שורה הכרחית

15 דקות

הפרומפט לא נכתב כך "כי כך". כל קטע מגדיר "גדר" שמונע מה-AI לסטות לכיוון לא רצוי. הטבלה הבאה מסבירה כל חלק.

קטע מהפרומפטלמה הוא הכרחי
You are a senior backend engineer specializing in Google Apps Script. Role Assignment: AI מייצר קוד ברמה גבוהה יותר כשמגדירים לו תפקיד מומחה. "Backend engineer" מונע מהסקריפט לכלול קוד Frontend.
Do NOT generate any HTML or CSS. Output ONLY the .gs code Output Scoping: ללא הנחיה זו, AI נוטה להוסיף HTML "שימושי" שמבלבל בין הקבצים ושובר את ההדבקה לעורך.
TIER 1 — Yahoo Finance... TIER 2 — Alpha Vantage... TIER 3 — Google Finance Fallback Architecture: הגדרת סדר מפורשת מונעת מה-AI לבחור מקור אחד ולהתעלם מהשאר. ה"סדר" חשוב — Yahoo ראשון כי מהיר וחינמי.
var AV_KEY = 'YOUR_ALPHA_VANTAGE_KEY'; Key Placement: מבטיח שה-AI ישים את המפתח בתוך ה-.gs ולא ב-HTML. Placeholder ברור = לא תשכחו להחליף.
Beta = Covariance(...) / Variance(...) Calculation Spec: בלי נוסחה מפורשת, ה-AI עשוי להשתמש ב-Beta משוער או להוריד מ-API. נוסחה מדויקת = חישוב עצמאי אמין.
signal_reason must be a short Hebrew string Language Constraint: מבטיח שהסבר ההמלצה יגיע בעברית ישירות מהשרת — לא תצטרכו לתרגם ב-Frontend.
Do NOT use SpreadsheetApp or any Sheets-related service. Dependency Ban: AI "מכיר" GAS בעיקר בהקשר של Sheets. ללא איסור מפורש — עלול להוסיף SpreadsheetApp.getActiveSpreadsheet() שיישבר ב-Standalone.
If Beta calculation fails... use Beta = 1.0 as default. Graceful Degradation: SPY לפעמים מחזיר נתונים חסרים. Beta=1.0 (ניטרלי) מבטיח שה-CAPM ימשיך לפעול גם כשאין מספיק היסטוריה.

הדביקו לעורך GASחזרו לחלון script.google.com, לחצו בתוך העורך הריק, Ctrl+V. הקוד אמור למלא את המסך.

פרסום כ-Web App — Deploy

15 דקות — השלב הקריטי!

Deploy — הפיכת הסקריפט ל-API חי

מה זה בכלל Deploy?
"פרסום" (Deploy) הוא הרגע שבו גוגל לוקחת את הקוד השמור שלנו ומפעילה אותו על שרת ציבורי, עם כתובת URL קבועה. רק אז הסקריפט מגיב לבקשות מהאינטרנט. בלי Deploy — הקוד קיים אבל "ישן" בענן ולא נגיש לאף אחד.
הגדרות שגויות = אפליקציה שבורה
שלושה שדות קריטיים ב-Deploy. טעות באחד מהם — ה-URL לא יגיב, ידרוש Login, או ירוץ עם הרשאות שגויות. עקבו בדיוק.
1
לחצו "Deploy" → "New deployment"הכפתור הכחול/ירוק בפינה הימנית עליונה של Apps Script Editor.
2
לחצו על גלגל השיניים ⚙️ → בחרו "Web app"ייפתח חלון הגדרות. תחת "Select type" לחצו על הגלגל ובחרו Web app בדיוק — לא "API executable", לא "Add-on".
3
הגדרה 1 — Execute as: Me (your email)הסקריפט ירוץ עם ההרשאות שלכם. כך ה-API Key שהכנסתם פועל — הוא בחשבון שלכם.
4
הגדרה 2 — Who has access: Anyoneלא "Anyone with Google Account" — זה דורש Login. Anyone = כל URL call עובד ישירות, כולל מה-HTML Frontend שיבנה קובץ 3.
5
לחצו "Deploy" ואשרו הרשאותGoogle תבקש אישור גישה. לחצו "Authorize access" → בחרו את חשבונכם → אם מופיעה "Google hasn't verified this app" — לחצו "Advanced" ← "Go to Business Intelligence Script (unsafe)". זה בטוח — זה הקוד שלכם.
6
✅ העתיקו את ה-Web App URL!לאחר Deploy מוצלח, Google מציגה URL בפורמט:
https://script.google.com/macros/s/AKfycbXXXXXXXX/exec
שמרו אותו! הוא ה-"כתובת השרת" שתזינו בקובץ 3.
לכל שינוי עתידי בקוד — Deploy מחדש!
שמירה לבד לא מעדכנת את ה-URL הקיים. לאחר כל שינוי: Deploy → Manage deployments → עיפרון ✏️ → Version: "New version" → Deploy. אותו URL, קוד חדש.

בדיקת ה-Endpoint — האם הסקריפט עובד?

10 דקות

בדיקות שלב-אחר-שלב

מה זה "Endpoint"?
Endpoint הוא פשוט כתובת URL שמקבלת בקשות ומחזירה נתונים. ה-URL שקיבלתם לאחר ה-Deploy הוא ה-Endpoint שלכם. בדיוק כמו שאתם פותחים URL של אתר — אתם פותחים URL של ה-API שלכם, רק שבמקום דף HTML מקבלים JSON.

לפני שנבנה את ה-Frontend, נוודא שהסקריפט מגיב כהלכה. כל הבדיקות הבאות מתבצעות ישירות בדפדפן — פשוט הכניסו את הכתובת לשורת ה-URL:

בדיקת Health Check
הכניסו בדפדפן:
[YOUR_URL]/exec?action=health תשובה מצופה:
{"status":"ok","timestamp":"...","version":"2.0"}
💡 אם הדפדפן מציג JSON — הכל תקין. אם מופיעה שגיאה — ראו סעיף 8.
בדיקת ניתוח מניה
[YOUR_URL]/exec?symbol=AAPL&action=analyze תשובה מצופה: JSON עם currentPrice, beta, capm_expected, alpha, signal ועוד. הטעינה עשויה לקחת 3-8 שניות בקריאה הראשונה (Cold Start = "התעוררות" השרת).
💡 לא מבינים את ה-JSON שמופיע? זה נורמלי — ה-Frontend בקובץ 3 יהפוך אותו לגרפים וכרטיסים יפים.
בדיקת ייצוא CSV
[YOUR_URL]/exec?symbol=MSFT&action=csv תשובה מצופה: טקסט CSV עם שורות Date,Close,Volume,Daily_Return. אמור להוריד אוטומטית או להציג כטקסט.
בדיקת Nocache
[YOUR_URL]/exec?symbol=TSLA&nocache=1 תשובה מצופה: JSON זהה אבל עם "cached":false — מראה שהסקריפט קורא מ-API חי.
