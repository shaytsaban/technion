למה GAS עכשיו — לפני שסיימנו SQL?

הסיבה פשוטה ועמוקה: בעולם הטכנולוגיה, MVP (Minimum Viable Product) — מוצר קטן ועובד — שווה יותר מהבטחה לפרויקט מושלם שמגיע בשנה הבאה.

הסבר מונח: MVP
MVP — Minimum Viable Product (מוצר בר-קיימא מינימלי): הגרסה הקטנה ביותר של מוצר שעדיין עובדת ומספקת ערך אמיתי. הרעיון: "צא לשוק מהר, למד מהמשתמשים, שפר." SQL מושלם ייקח עוד חודשים — אבל יישום עובד אפשר לבנות היום.

הדמיון שאהוב עליי: SQL הוא מחסן ענק וממוחשב — מסודר, חזק, ומסוגל לנהל מיליוני מוצרים. אבל לשלוח את הסחורה ישירות ממנו ללקוחות? זה דורש תשתית עצומה. Google Apps Script הוא ואן המשלוחים האגילי: לוקח מה שיש, ומגיע ללקוח מחר בבוקר.

Google Apps Script עצמאי — ללא Google Sheets

10 דקות

מה זה GAS ולמה לא צריך Sheets?

Google Apps Script (GAS) הוא כלי של Google שמאפשר לכתוב קוד JavaScript שרץ על שרתי Google. אנחנו לא צריכים שרת משלנו, לא משלמים, ולא צריכים להתקין כלום.

בגרסה הקודמת של השיעור דרשנו Google Sheets כ"מסד נתונים". היום נסיר את ההגבלה הזו: GAS יכול לעמוד לבד — לקבל בקשות מהאינטרנט, לשאוב נתונים חיים, לעבד אותם, ולהחזיר תשובות. ללא Sheets, ללא הגבלת 50,000 שורות, ללא תלות.

הסבר מונח: Standalone Script
Standalone Script = סקריפט GAS שלא שייך לאף קובץ Google ספציפי (לא Sheet, לא Doc). יוצרים אותו ישירות ב-script.google.com ופורסים אותו כ-Web App עם URL עצמאי. זה מה שנעשה.
הסבר מונח: Web App
Web App = יישום רשת. כשפורסים סקריפט GAS כ-Web App, גוגל מקצה לו URL ציבורי. כל מי שיגש ל-URL הזה (דפדפן, אפליקציה, כל דבר) יקבל את התשובה שהסקריפט מחזיר. בדיוק כמו שרת אמיתי.

מה הסקריפט יכול לעשות?

הסקריפט שלנו יוגדר לבצע את הפעולות הבאות:

  • 📡 לשלוח בקשות HTTP ל-API חיצוני (Yahoo Finance, Alpha Vantage)
  • 📊 לעבד נתונים פיננסיים: חישוב Beta, Sharpe Ratio, CAPM Expected Return
  • 💾 לשמור זמנית ב-Cache כדי לא לחרוג ממכסות
  • 📤 להחזיר JSON לממשק ה-HTML
  • 📥 לייצא CSV עם כל הנתונים ההיסטוריים
חשוב מאוד: מה לא יעשה הסקריפט
הסקריפט לא יציג ממשק גרפי — זה תפקיד ה-HTML. הוא רק מחזיר מידע גולמי (JSON/CSV). ממש כמו מלצר שמביא את האוכל — הוא לא מעצב את הצלחת, הוא רק מביא אותה.

API — מה זה, מאיפה לוקחים, ואיפה שמים?

15 דקות — חיוני להבנה!

מה זה API?

API (Application Programming Interface) — בעברית: "ממשק תכנות יישומים". נשמע טכני? בואו נפשט.

דמיינו מסעדה. אתם (האפליקציה שלנו) יושבים בשולחן. במטבח (השרת) יש שפים מוכשרים עם כל הנתונים. הבעיה: אתם לא יכולים להיכנס למטבח. ה-API הוא המלצר — האיש שמעביר את ההזמנה שלכם למטבח ומחזיר לכם את הצלחת.

האפליקציה שלנו

🤝
ה-API (ממשק)
מקבל בקשה בפורמט מוגדר, מעביר לשרת, מחזיר תשובה מובנית
🏦
Yahoo Finance / Alpha Vantage
מסד הנתונים של מחירי המניות. מיליוני נתונים שמתעדכנים בזמן אמת
הסבר מונח: JSON
JSON (JavaScript Object Notation) — פורמט תשובה סטנדרטי של APIs. נראה כך:
{"symbol":"AAPL","price":189.3,"change_pct":0.85}
זה פשוט מילון של שם=ערך, שגם בני אדם וגם מחשבים יכולים לקרוא בקלות.

מה זה API Key — ולמה צריך אותו?

API Key הוא קוד ייחודי — כמו מספר לקוח VIP — שמזהה מי שולח את הבקשה. השרת בודק: "האם המפתח הזה מוכר לי? האם הוא שילם? האם הוא לא עבר את המכסה?" ורק אז מחזיר נתונים.

Alpha Vantage מחלקים מפתח חינמי — אבל גם חינמי דורש זיהוי, כדי שיוכלו לספור כמה בקשות שלחתם ביום.

כלל ברזל: API Key הולך בסקריפט — לא ב-HTML!
זה הכלל הכי חשוב בארכיטקטורה שלנו. לעולם אל תכניסו API Key לתוך קובץ HTML שמגיע למשתמש. קובץ HTML ניתן לצפייה על ידי כל אחד (לחיצה ימנית → "View Source"). מישהו יגנוב את המפתח ויהיה אתם!

✅ נכון: Key בסקריפט GAS

הסקריפט רץ על שרת Google. המשתמש רואה רק את ה-URL הסופי — לא את הקוד. ה-Key בטוח.

var API_KEY = 'SYOD0OLV...';
← בתוך הסקריפט .gs ✅

❌ שגוי: Key בממשק HTML

כל גולש יכול ללחוץ F12 ולראות את המפתח. סכנת גניבה ושימוש לרעה!

const API_KEY = 'SYOD0OLV...';
← בתוך ה-.html ❌ אסור!

מודל CAPM — הלב הפועם של ניתוח ההשקעות

25 דקות — ה-section החשוב ביותר!

מה זה CAPM ולמה הוא מהפכני?

עד השנות ה-60 של המאה ה-20, ניתוח מניות היה בעיקר "אומנות" — אנליסטים השתמשו בניסיון, אינטואיציה, ותחושות בטן. ב-1964 שינה William Sharpe את העולם עם מאמר אחד שהביא לו פרס נובל בכלכלה (1990).

הרעיון: ניתן לכמת מתמטית כמה תשואה "מגיעה" לך על מניה, בהתחשב בסיכון שלקחת. אם המניה נותנת יותר ממה שמגיע לה לפי הנוסחה — כנראה כדאי לקנות. אם פחות — כנראה כדאי למכור.

הסבר מונח: CAPM
CAPM — Capital Asset Pricing Model (מודל תמחור נכסי הון): מודל פיננסי מתמטי שקובע מה צריכה להיות התשואה המצופה על נייר ערך, בהינתן רמת הסיכון שלו ביחס לשוק. פותח ב-1964 על ידי William Sharpe, בנוי על עבודה קודמת של Harry Markowitz.

הנוסחה — ופירוק כל רכיב

זו הנוסחה שתנהל את כל ההחלטות בניתוח שלנו:

E(Rᵢ) = Rf + βᵢ × [E(Rm) - Rf]
נקראת: "התשואה המצופה על נכס i שווה לריבית חסרת סיכון פלוס Beta כפול פרמיית הסיכון של השוק"
E(Rᵢ)
התשואה המצופה
כמה אחוז תשואה "אמורה" לתת המניה לפי רמת הסיכון שלה. זה מה שנחשב ונשווה למה שקרה בפועל.
Rf
ריבית חסרת סיכון
התשואה שניתן לקבל ללא שום סיכון — בדרך כלל אג"ח ממשלתי ל-10 שנים של ארה"ב. כיום: ~4.25% לשנה.
βᵢ (Beta)
מקדם הסיכון השיטתי
כמה מניה נעה ביחס לשוק הכללי. Beta=1 = זזה כמו השוק. Beta=2 = זזה פי 2. Beta=0.5 = חצי תנודתיות.
E(Rm)
תשואת השוק המצופה
התשואה הממוצעת ארוכת-הטווח של השוק הכללי (S&P 500). היסטורית: ~10% לשנה. בסקריפט נשתמש ב-10%.
E(Rm) - Rf
פרמיית סיכון השוק
הפיצוי שמשקיע מקבל על כך שהוא לוקח סיכון שוק במקום להשאיר את הכסף בפיקדון בטוח. ~10% - 4.25% = ~5.75%.
α (Alpha)
תשואה עודפת (לא בנוסחה)
ההפרש בין מה שהמניה הניבה בפועל לבין מה שה-CAPM ניבא שהיא אמורה להניב. Alpha חיובי = המניה "הפתיעה לטובה".

דוגמה מחושבת — Apple (AAPL)

בואו נעבור דוגמה מספרית שלמה:

נתוני הדוגמה
  • Beta של AAPL: 1.25 (זזה 25% יותר מהשוק)
  • ריבית חסרת סיכון (Rf): 4.25% לשנה
  • תשואת שוק מצופה E(Rm): 10% לשנה
  • תשואת AAPL בפועל (3 חודשים, אנואליזד): 18%
החישוב

E(Rᵢ) = 4.25% + 1.25 × (10% - 4.25%)
E(Rᵢ) = 4.25% + 1.25 × 5.75%
E(Rᵢ) = 4.25% + 7.19%
E(Rᵢ) = 11.44%

תוצאה: לפי CAPM, AAPL "אמורה" להניב ~11.44% לשנה. אבל בפועל היא הניבה 18%. Alpha = 18% - 11.44% = +6.56% — חיובי! זה אות לקנייה.

כלל ההחלטה CAPM — קנה/החזק/מכור

הכלל שהאפליקציה שלנו תממש:

📈
קנה (BUY)
תנאי: Alpha > +2%
כלומר: המניה הניבה בפועל יותר מ-2% מעל מה ש-CAPM מצפה. היא "מתומחרת בחסר".
⚖️
החזק (HOLD)
תנאי: Alpha בין -2% ל-+2%
המניה בהתאמה סבירה למה שמצפים ממנה לפי הסיכון. אין פעולה ברורה.
📉
מכור (SELL)
תנאי: Alpha < -2%
כלומר: המניה מניבה פחות מ-2% מתחת לציפיות לפי הסיכון. היא "מתומחרת ביתר".
אזהרה: CAPM הוא כלי — לא אורקל
CAPM מבוסס על הנחות רבות שלא תמיד מתקיימות: שהשווקים יעילים, שה-Beta יציב לאורך זמן, שהמשקיע מפוזר לחלוטין. הוא נקודת פתיחה לניתוח — לא החלטה סופית. לעולם לא להשקיע אמיתי על בסיס כלי זה בלבד!

Beta, Sharpe Ratio — כלי ההעמקה

15 דקות

Beta — כמה "בר-סיכון" המניה?

Beta הוא אחד המדדים החשובים ביותר בפיננסים. הוא מודד כמה מניה מושפעת מתנועות השוק הכללי. נחשב כמתאם (Correlation) בין תשואות המניה לתשואות S&P 500.

סקאלת Beta — כיצד לקרוא את המדד
β < 0β = 0.5β = 1.0β = 1.5β > 2.0
β < 0
הפוך לשוק
כשהשוק עולה — יורד. דוגמה: זהב, VIX.
β = 0.5
פחות תנודתי
כשהשוק עולה 10% — עולה 5%. מניות utility, מזון.
β = 1.0
כמו השוק
זז בדיוק כמו S&P 500. ETF מדדי.
β > 1.5
תנודתי מהשוק
כשהשוק עולה 10% — עולה 15%+. מניות טכנולוגיה, Tesla.
כיצד הסקריפט מחשב Beta?
הסקריפט ייחשב Beta באמצעות Covariance/Variance על סמך נתונים היסטוריים:
β = Covariance(Rstock, Rmarket) / Variance(Rmarket)
זאת אומרת: ניקח 60 ימי מסחר אחרונים של המניה ושל ה-SPY (תעודת סל של S&P 500), נחשב את הקשר ביניהם.

Sharpe Ratio — תשואה מותאמת סיכון

Beta מספר לנו כמה תנודתי נכס. אבל מה אם נכס תנודתי מאוד נותן תשואה גבוהה מאוד? האם זה עדיין כדאי? כאן נכנס Sharpe Ratio.

הנוסחה

Sharpe Ratio = (Rp - Rf) / σp

  • Rp: תשואת התיק/מניה בפועל
  • Rf: ריבית חסרת סיכון (4.25%)
  • σp: סטיית התקן של התשואות (מדד התנודתיות)
Sharpe Ratioפרשנותדוגמה
< 0גרוע מהחזקת מזומן — הפסד ביחס לסיכוןמניה שירדה תוך תנודתיות גבוהה
0 – 0.5חלש — לא מגמול מספיק על הסיכוןאג"ח קונצרני
0.5 – 1.0סביר — רוב תיקי המניותS&P 500 ממוצע שנתי
1.0 – 2.0טוב — תיק מנוהל היטבקרנות גידור מובילות
> 2.0מצוין — נדיר בשוק אמיתיWarren Buffett: ~0.79 ממוצע!
למה Sharpe חשוב לנו?
דמיינו שתי מניות: A נתנה 20% תשואה עם סטייה של 5%, B נתנה 20% עם סטייה של 30%. לכאורה שוות — אבל Sharpe של A הוא 3.15 ושל B הוא 0.53. A הרבה יותר טובה — אותה תשואה, הרבה פחות לחץ ולחץ ולב.

כיצד CAPM + Beta + Sharpe עובדים יחד באפליקציה

לוגיקת ההחלטה המלאה בסקריפט
  1. חישוב Beta מ-60 ימי מסחר (ביחס ל-SPY)
  2. חישוב E(Rᵢ) לפי נוסחת CAPM עם Rf=4.25%, E(Rm)=10%
  3. חישוב תשואה בפועל — אנואליזציה של 3 חודשים אחרונים
  4. חישוב Alpha = תשואה בפועל - E(Rᵢ)
  5. חישוב Sharpe Ratio מסטיית התקן של ה-60 ימים
  6. החלטה: Alpha > +2% ו-Sharpe > 0.5 → BUY | Alpha בין ±2% → HOLD | Alpha < -2% → SELL

שאלה 1 מתוך 9
מהו ה-GAS Script שנבנה בשיעור זה, ביחס ל-Google Sheets?
א
חלק מ-Google Sheets — תמיד צריך גיליון פתוח כדי שיעבוד

הסבר מפורט
תשובה נכונה: ב. הסקריפט שנבנה הוא Standalone Script — עצמאי לחלוטין. הוא נוצר ישירות ב-script.google.com, לא מתוך Sheets, ורץ על שרתי Google כ-Web App עם URL עצמאי.

למה לא א? Bound Script (מקושר ל-Sheets) הוא סוג אחר — מתאים לאוטומציה של גיליון ספציפי. אנחנו צריכים API שמגיב לכל בקשה ממי שיש לו את ה-URL.
למה לא ג? GAS רץ על שרתי Google — לא על המחשב. זה לא תוסף מקומי.
למה לא ד? זה ממש לא Excel. GAS הוא JavaScript שרץ בענן גוגל.

ג'ון רוצה לכלול API Key של Alpha Vantage ביישום שלו. איפה הוא צריך לשים אותו?

הכלל הזהב: סודות שייכים לשרת. ממשק שייך ללקוח.

מדוע הסקריפט שלנו משתמש ב-CacheService.getScriptCache() עם TTL של 3600 שניות?
א
כדי לשמור את ה-API Key בצורה מוצפנת
ב
כדי לא לקרוא ל-API בכל בקשה — שמירת התוצאה שעה אחת מונעת חריגה ממכסת ה-Quota היומית
ג

ד
כדי להאיץ את זמן ה-Deploy בעת פרסום גרסה חדשה
הסבר מפורט
תשובה נכונה: ב. CacheService שומר את תוצאת הקריאה ל-API בזיכרון שרתי Google למשך 3600 שניות (שעה). כך, אם 100 משתמשים מבקשים נתוני AAPL באותה שעה — ה-API נקרא פעם אחת בלבד, לא 100 פעמים.

חשבון מכסה: Alpha Vantage חינמי = 500 קריאות ביום. בלי Cache, 500 משתמשים מצרכים את כל המכסה. עם Cache — ניתן לשרת אלפי משתמשים.

TTL (Time To Live) = כמה זמן התוצאה "חיה" ב-Cache. 3600 שניות = שעה אחת.

א
היא נקודת הכניסה של ה-Web App — Google מריצה אותה אוטומטית בכל פנייה ל-URL (HTTP GET), ומחזירה JSON/CSV בחזרה

היא פונקציה שמופעלת רק ידנית על ידי המפתח מתוך ה-Editor
ג
היא אחראית על ציור הגרפים ב-Chart.js
ד
היא מאמתת את ה-API Key מול Alpha Vantage לפני כל קריאה
הסבר מפורט
תשובה נכונה: א. ב-GAS Web App, הפונקציה doGet(e) היא ה"שומר סף" — Google מריצה אותה בכל פעם שמישהו פונה ל-URL.

הפרמטר e מכיל את כל הפרמטרים שהועברו ב-URL. למשל: .../exec?symbol=AAPL&action=csv → ניגש אליהם כ-e.parameter.symbol.

למה לא ב? פונקציות שמופעלות ידנית נקראות בשם כלשהו — doGet ספציפית היא Reserved Name של Google לכניסה ל-Web App.
