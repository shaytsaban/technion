INNER JOIN — שורות בלי התאמה נעלמות

INNER JOIN (זה שהשתמשנו בו עד היום, וזו ברירת המחדל) שומר רק שורות שיש להן התאמה בשתי הטבלאות. לחץ וחבר — וראה מה קורה למאיה:

⑤ BigQuery · INNER מול LEFT ☁️

כמה לקוחות "נעלמים" באמת?

נספור כמה משתמשים מופיעים כשמחברים אותם להזמנות — פעם עם INNER, פעם עם LEFT. ההפרש = המשתמשים שמעולם לא הזמינו, ש-INNER השמיט בשקט.

  1. פתח את BigQuery Sandbox והתחבר עם חשבון Google.
  2. הרץ את שאילתה א' (INNER) ואת שאילתה ב' (LEFT). השווה את שני המספרים.
א' · INNER — רק משתמשים עם הזמנות
SELECT COUNT(DISTINCT u.id) AS users_appearing
FROM `bigquery-public-data.thelook_ecommerce.users` u
JOIN `bigquery-public-data.thelook_ecommerce.orders` o
  ON u.id = o.user_id;
ב' · LEFT — כל המשתמשים
-- LEFT שומר גם את מי שאין לו הזמנה
SELECT COUNT(DISTINCT u.id) AS users_appearing
FROM `bigquery-public-data.thelook_ecommerce.users` u
LEFT JOIN `bigquery-public-data.thelook_ecommerce.orders` o
  ON u.id = o.user_id;
💥 המספר ב-ב' גדול יותר. ההפרש = משתמשים בלי הזמנה. אם דוח "סך לקוחות" מבוסס על INNER JOIN — הוא מדווח חסר, בלי אזהרה.

ה-NULL של LEFT הוא לא רק טכני — הוא מאפשר לענות על שאלה שאי אפשר אחרת: מי לא קנה?

Anti-join: למצוא שורות ללא התאמה

הטריק: LEFT JOIN ואז WHERE right IS NULL — משאיר רק את מי שאין לו התאמה. זה הכלי ל"לקוחות שמעולם לא קנו".

  1. הרץ את שאילתה ג' — כמה משתמשים מעולם לא ביצעו הזמנה.
  2. הרץ את שאילתה ד' — מספר ההזמנות לכל משתמש, כולל 0 למי שלא קנה.
ג' · משתמשים שמעולם לא הזמינו (anti-join)
-- LEFT JOIN + WHERE על NULL = רק מי שאין לו התאמה
SELECT COUNT(*) AS users_never_ordered
FROM `bigquery-public-data.thelook_ecommerce.users` u
LEFT JOIN `bigquery-public-data.thelook_ecommerce.orders` o
  ON u.id = o.user_id
WHERE o.user_id IS NULL;
ד' · הזמנות לכל משתמש (כולל 0)
-- COUNT על העמודה מהצד הימני מתעלם מ-NULL, אז מי שלא הזמין מקבל 0
SELECT u.id, COUNT(o.order_id) AS order_count
FROM `bigquery-public-data.thelook_ecommerce.users` u
LEFT JOIN `bigquery-public-data.thelook_ecommerce.orders` o
  ON u.id = o.user_id
GROUP BY u.id
ORDER BY order_count ASC
LIMIT 10;
✅ "מי לא קנה" היא שאלה עסקית יקרת ערך (לקמפיין החזרה) — ואי אפשר לענות עליה עם INNER, כי הוא בדיוק משמיט את התשובה. LEFT + IS NULL הוא הכלי.

⑦ BigQuery · חיבור רב-טבלאות ☁️

לחבר שלוש טבלאות בשרשרת

שאלה אמיתית נוגעת בכמה טבלאות: פריטים → הזמנות → משתמשים. מחברים אותן בשרשרת, JOIN אחרי JOIN.

  1. הרץ את שאילתה ה' — הכנסה לפי מדינת הלקוח (פריטים → משתמשים).
  2. הרץ את שאילתה ו' — שרשרת של 3 טבלאות: פריטים → הזמנות → משתמשים, פילוח לפי מדינה וסטטוס.
ה' · הכנסה לפי מדינה
SELECT u.country, ROUND(SUM(oi.sale_price)) AS revenue
FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
JOIN `bigquery-public-data.thelook_ecommerce.users` u
  ON oi.user_id = u.id
GROUP BY u.country
ORDER BY revenue DESC
LIMIT 10;
ו' · שרשרת 3 טבלאות
-- כל JOIN מוסיף טבלה לשרשרת לפי המפתח שלה
SELECT u.country, o.status, COUNT(*) AS items
FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
JOIN `bigquery-public-data.thelook_ecommerce.orders` o
  ON oi.order_id = o.order_id
JOIN `bigquery-public-data.thelook_ecommerce.users` u
  ON o.user_id = u.id
GROUP BY u.country, o.status
ORDER BY items DESC
LIMIT 10;
⚠️ תזכורת ממודול 1: JOIN על מפתח לא-ייחודי יכול גם לשכפל שורות (fan-out) ולנפח סכומים. תמיד ודא שאתה מחבר מפתח אל מפתח נכון.

איזה JOIN לכל שאלה?

הכלל: רוצה רק התאמות → INNER. רוצה לשמור את כל צד אחד → LEFT. רוצה למצוא את מי שאין לו התאמה → LEFT + IS NULL. החלט:

"הכנסות לפי מוצר" — רק מוצרים שנמכרו מעניינים
"כל המוצרים בקטלוג, עם כמות שנמכרה (0 אם לא נמכר)"

סיימת — ואתה כבר לא מאבד שורות בשקט

  • INNER JOIN = רק התאמות בשתי הטבלאות — שורות יתומות נעלמות
  • LEFT JOIN = כל השמאלית + NULL היכן שאין התאמה
  • RIGHT / FULL = כל הימנית / הכול משתיהן
  • Anti-join (LEFT + WHERE IS NULL) = למצוא את מי שאין לו התאמה
  • שרשרת JOIN-ים מחברת כמה טבלאות — ושים לב ל-fan-out על מפתח לא-ייחודי
