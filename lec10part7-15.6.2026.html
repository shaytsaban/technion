③ המתכון

OVER — שלושה חלקים

המבנה תמיד אותו דבר: פעולה, ואחריה OVER (...) שמגדיר את החלון.

המתכון הכללי
SUM(sale_price) OVER (
  PARTITION BY category   -- חלק לקבוצות (כמו GROUP BY, בלי לכווץ)
  ORDER BY day            -- הסדר לחישוב מצטבר
)
OVER = "הסתכל על חלון של שורות, אבל השאר את השורה שלי". PARTITION BY = חלק לקבוצות (כמו GROUP BY, אך בלי לכווץ — הדירוג/המצטבר מתאפס לכל קבוצה). ORDER BY = באיזה סדר לחשב (חיוני למצטבר ולהשוואת תקופות). שני האחרונים אופציונליים.

שלוש הפונקציות הנפוצות — התאם כל אחת לתפקידה:

RANK() / ROW_NUMBER()
SUM() OVER (ORDER BY ...)
LAG()

התאם את שלוש הפונקציות.

④ BigQuery · מצטבר ☁️

סכום מצטבר ואחוז מהסך-הכול

נסכם הכנסה לכל חודש, ולצידה את הסכום המצטבר. ההבדל הקטן: ORDER BY בתוך OVER הופך סכום למצטבר; בלעדיו זה הסך-הכול הגלובלי.

  1. פתח את BigQuery Sandbox והתחבר עם חשבון Google.
  2. הרץ את שאילתה א' — הכנסה חודשית + מצטבר עולה.
  3. הרץ את שאילתה ב' — חלקה של כל קטגוריה מסך ההכנסות (OVER ריק = הסך-הכול).
א' · הכנסה חודשית + מצטבר
-- קודם מסכמים לכל חודש (CTE), ואז סוכמים מצטבר לפי סדר החודשים
WITH monthly AS (
  SELECT
    DATE_TRUNC(DATE(created_at), MONTH) AS month,
    SUM(sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items`
  GROUP BY month
)
SELECT
  month,
  ROUND(revenue) AS revenue,
  ROUND(SUM(revenue) OVER (ORDER BY month)) AS running_total
FROM monthly
ORDER BY month;
ב' · חלק כל קטגוריה מהסך-הכול
-- OVER () ריק = סכום על כל השורות = הסך-הכול הגלובלי
WITH cat AS (
  SELECT p.category, SUM(oi.sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
  JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
  GROUP BY p.category
)
SELECT category, ROUND(revenue) AS revenue,
  ROUND(revenue / SUM(revenue) OVER () * 100, 1) AS pct_of_total
FROM cat ORDER BY revenue DESC;

⑤ BigQuery · דירוג ☁️

RANK ו-ROW_NUMBER — לדרג בלי לאבד שורות

נדרג מוצרים לפי הכנסה. RANK נותן דירוג עם דילוגים בתיקו (1,1,3); ROW_NUMBER נותן מספור רץ ייחודי תמיד (1,2,3).

  1. הרץ את שאילתה ג' — דירוג המוצרים בהכנסה (RANK).
  2. הרץ את שאילתה ד' — אותו דבר עם ROW_NUMBER, וראה את ההבדל בתיקו.
ג' · דירוג מוצרים בהכנסה (RANK)
SELECT
  p.name,
  ROUND(SUM(oi.sale_price)) AS revenue,
  RANK() OVER (ORDER BY SUM(oi.sale_price) DESC) AS revenue_rank
FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
GROUP BY p.name
ORDER BY revenue_rank
LIMIT 10;
ד' · אותו דבר עם ROW_NUMBER
-- ROW_NUMBER תמיד ייחודי — אין שני "מקום ראשון"
SELECT
  p.name,
  ROUND(SUM(oi.sale_price)) AS revenue,
  ROW_NUMBER() OVER (ORDER BY SUM(oi.sale_price) DESC) AS row_num
FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
GROUP BY p.name
ORDER BY row_num
LIMIT 10;

⑥ BigQuery · השוואה ומובילים ☁️

LAG (חודש קודם) ו-PARTITION BY (המוביל בכל קטגוריה)

שתי השאילתות שאנליסט BI כותב הכי הרבה: שינוי חודש-מול-חודש, והמוצר המוביל בתוך כל קטגוריה.

  1. הרץ את שאילתה ה' — הכנסה חודשית מול החודש הקודם (LAG), וההפרש ביניהם.
  2. הרץ את שאילתה ו' — המוצר הנמכר ביותר בכל קטגוריה (PARTITION BY מאתחל את הדירוג לכל קטגוריה).
ה' · שינוי חודש-מול-חודש (LAG)
-- LAG מחזיר את הערך של השורה הקודמת בסדר
WITH monthly AS (
  SELECT DATE_TRUNC(DATE(created_at), MONTH) AS month,
    SUM(sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items`
  GROUP BY month
)
SELECT
  month,
  ROUND(revenue) AS revenue,
  ROUND(LAG(revenue) OVER (ORDER BY month)) AS prev_month,
  ROUND(revenue - LAG(revenue) OVER (ORDER BY month)) AS change
FROM monthly ORDER BY month;
ו' · המוצר המוביל בכל קטגוריה
-- PARTITION BY category = הדירוג מתחיל מחדש לכל קטגוריה; משאירים רק מקום 1
WITH cat_sales AS (
  SELECT p.category, p.name, SUM(oi.sale_price) AS revenue
  FROM `bigquery-public-data.thelook_ecommerce.order_items` oi
  JOIN `bigquery-public-data.thelook_ecommerce.products` p ON oi.product_id = p.id
  GROUP BY p.category, p.name
),
ranked AS (
  SELECT *,
    ROW_NUMBER() OVER (PARTITION BY category ORDER BY revenue DESC) AS rn
  FROM cat_sales
)
SELECT category, name, ROUND(revenue) AS revenue
FROM ranked WHERE rn = 1
ORDER BY revenue DESC;
✅ שאילתה ו' כמעט בלתי אפשרית בלי פונקציות חלון — "המוביל בכל קבוצה" היא בדיוק מה ש-PARTITION BY נועד אליו. זה כלי הדגל של אנליסט BI.

⑦ החלטה

חלון או GROUP BY?

הכלל הפשוט: רוצה שורה אחת לכל קבוצה (איבוד הפירוט) — GROUP BY. רוצה לשמור כל שורה ולהוסיף לה עמודה — פונקציית חלון. החלט בכל מקרה:

"סך מכירות לכל קטגוריה" (טבלה קצרה, שורה לקטגוריה)
"כל מכירה, ולצידה דירוג המוצר שלה" (כל השורות נשמרות)
"מכירות כל חודש, ולצידן ההפרש מהחודש הקודם"

סיימת — שדרגת את הניתוח שלך

  • פונקציית חלון = שומרת כל שורה, מוסיפה עמודה מחושבת (בניגוד ל-GROUP BY שמכווץ)
  • המתכון: FUNC() OVER (PARTITION BY ... ORDER BY ...)
  • SUM OVER (ORDER BY) = מצטבר · OVER () = הסך-הכול / אחוז מהסך
  • RANK / ROW_NUMBER = דירוג · LAG = השוואה לתקופה קודמת
  • PARTITION BY = "המוביל בכל קבוצה" — דגל הניתוח של אנליסט BI
