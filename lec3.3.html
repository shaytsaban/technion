Frontend לעומת Backend — הבנת ההפרדה

8 דקות

מדוע שני פרומפטים נפרדים?

שאלה שרבים שואלים: "למה לא לבקש מה-AI לכתוב הכל בפרומפט אחד?" התשובה פרקטית לחלוטין:

היבטפרומפט אחד (לא מומלץ)שני פרומפטים (כפי שעשינו)
איכות הקודAI מבלבל בין Backend ל-Frontend, מוסיף SpreadsheetApp בתוך HTMLכל פרומפט מתמקד בתפקיד אחד — קוד נקי יותר
שגיאותקשה לאתר — הקוד שזור יחדקל לתקן — כל שכבה עצמאית
גמישותשינוי ב-UI = צריך לחזור על הכלשינוי ב-UI = רק מעדכנים את קובץ 3
API Keyעלול להגיע בתוך ה-HTML — סכנת אבטחה!Key תמיד בסקריפט בלבד
כלל מקצועי: "Separation of Concerns"
כל שכבה עושה דבר אחד בלבד. ה-Backend (קובץ 2) מספק נתונים. ה-Frontend (קובץ 3) מציג אותם. הם לא יודעים כיצד השני עובד פנימה — רק את ה"חוזה" ביניהם (פורמט ה-JSON).

הפרומפט ל-Frontend — העתיקו בדיוק

כללי שימוש

GAS_URL נשאר ריק בכוונה!
הפרומפט מכיל const GAS_URL = ''; — זה מכוון. תמלאו אותו בסעיף 6 לאחר שה-AI ייצור את הקובץ. אל תשנו שום דבר אחר בפרומפט.
טיפ לשימוש ב-AI
אם ה-AI מחזיר קוד שמתחיל ב-```html — העתיקו רק את מה שבין הגרשיים, ללא השורה הראשונה והאחרונה. הקוד עצמו מתחיל ב-<!DOCTYPE html>.

Signal box (id="signalBox"): large badge with signal text + signal_reason paragraph // === JAVASCRIPT: ANALYZE FLOW === async function analyze(): 1. Read symbol from input, trim and uppercase. 2. אנטומיה של הפרומפט — שורה אחרי שורה

12 דקות

כל שורה בפרומפט מתפקדת כ"גדר" שמונעת מה-AI לסטות. הטבלה הזו תלמד אתכם לכתוב פרומפטים מדויקים בעצמכם:

קטע מהפרומפטלמה הוא הכרחי
Output ONLY the HTML file — no explanations Output Scoping: ללא הנחיה זו, AI מוסיף הסברים לפני ואחרי הקוד שמונעים הדבקה ישירה. "ONLY" = קוד ולא כלום אחר.
const GAS_URL = ''; Placeholder מכוון: AI לא יודע את ה-URL שלכם — Placeholder ריק = תזכורת ברורה. בלי זה AI ממציא URL פיקטיבי שנראה תקין.
canvas id="priceChart", height=300px Chart.js Bug Prevention: ללא גובה מפורש, Canvas מתרחב לאינסוף ב-RTL. זהו הבאג הנפוץ ביותר עם Chart.js בעברית — גובה קבוע פותר אותו.
if (data.error) { showError(data.message); return; } Error Contract: מגדיר "חוזה" בין Backend ל-Frontend. הסקריפט מחזיר error:true? ה-HTML יודע בדיוק מה לעשות — מציג את ה-message בעברית.
Blob + URL.createObjectURL + a.click() CSV Download Mechanism: זהו המנגנון הסטנדרטי להורדת קבצים ב-JavaScript. ללא פירוט זה, AI עשוי לפתוח חלון חדש עם טקסט גולמי במקום להוריד קובץ.
Do NOT use localStorage, sessionStorage Environment Safety: ב-Incognito, iframe, ובסביבות מסוימות — storage חסום וזורק שגיאה. האיסור מכריח שימוש בזיכרון בלבד.
Never expose raw JavaScript Error objects UX Protection: שגיאת JS נראית כך: "TypeError: Cannot read properties of undefined (reading 'close')". למשתמש זה מבהיל. ההנחיה מכריחה תרגום לעברית ברורה.
dashboard hidden (display:none) on page load Clean Initial State: ללא הגדרה זו, לוח הנתונים יוצג ריק בעת פתיחת הדף — 0 בכל השדות, גרף ריק. חוויה מבלבלת. ה-hide/show מבטיח שהלוח מוצג רק עם נתונים אמיתיים.

חיבור ה-Frontend לסקריפט — הכנסת GAS_URL

10 דקות

5 צעדים לחיבור המלא

1
שמרו את הקוד כקובץ HTML לאחר שה-AI ייצר את הקוד — העתיקו אותו לקובץ טקסט חדש ושמרו בשם בדיוק: Business Intelligence Front.html ודאו שהסיומת היא .html ולא .txt.
2
פתחו את הקובץ בעורך טקסט לחצו ימני על הקובץ → "Open with" → בחרו Notepad (Windows) או TextEdit (Mac). לא כפול-לחיצה — זה יפתח בדפדפן.
3
חפשו את שורת GAS_URL השתמשו ב-Ctrl+F וחפשו: GAS_URL. תמצאו שורה כזו:
const GAS_URL = ''; // <-- user fills this after deployment
4
הכניסו את ה-URL שלכם בין המרכאות
const GAS_URL = 'https://script.google.com/macros/s/AKfycb.../exec';
שימו לב: ה-URL מתחיל ב-https ומסתיים ב-/exec. לא להוסיף ? או פרמטרים.
5
✅ שמרו (Ctrl+S) ופתחו בדפדפן עכשיו כפול-לחיצה על הקובץ. הממשק ייפתח. הקלידו AAPL ולחצו "נתח מניה".
שינוי עתידי בסקריפט — מתי GAS_URL משתנה?
ה-URL לא משתנה כשאתם עושים Deploy חדש על אותו Deployment קיים (Manage → Edit → New Version). הוא כן משתנה רק אם מחקתם את ה-Deployment וייצרתם חדש — מקרה נדיר.

הסבר מונח: CSV
CSV — Comma-Separated Values: קובץ טקסט פשוט שבו כל שורה היא רשומה, וכל עמודה מופרדת בפסיק. Excel, Google Sheets, Power BI, Python — כולם פותחים CSV ישירות. זה "הפורמט האוניברסלי" של נתונים.

ה-CSV שנייצא מכיל את כל הנתונים ההיסטוריים של המניה — 60 ימי מסחר — לניתוח מעמיק מחוץ לאפליקציה.

מה קורה אם המשתמש לוחץ 'נתח מניה' כשה-GAS_URL ריק?
א
שגיאת JavaScript גולמית מוצגת בדפדפן
ב
קריסה שקטה — לא קורה כלום
ג
הודעה עברית ידידותית מוצגת — 'שגיאה: יש להזין את כתובת ה-GAS...'
ד
הדפדפן מנסה לשלוח בקשה ל-URL ריק ומקבל שגיאת רשת
הסבר מפורט
תשובה נכונה: ג. הפרומפט הגדיר: if (GAS_URL === '') { alert("שגיאה..."); return; }

למה זה חשוב? ללא בדיקה זו, fetch('') שולח בקשה ל-URL ריק שמחזיר שגיאת רשת טכנית. "TypeError: Failed to fetch" לא אומר כלום למשתמש. הבדיקה מוקדמת = חוויה ידידותית.

עיקרון: תמיד אמתו קלט לפני ביצוע פעולה. זה נקרא "Fail Fast" — כשל מוקדם, ברור, ומובן.
שאלה 2 מתוך 4
מדוע ה-Dashboard מוסתר (display:none) בעת פתיחת הדף?
א
כדי לחסוך זיכרון דפדפן
ב
כדי שהמשתמש לא יראה לוח ריק עם 0 בכל השדות — הלוח מוצג רק עם נתונים אמיתיים
ג
כי Chart.js לא יכול לרנדר כשהדף נטען
ד
מסיבות אבטחה — המידע חסוי עד לאימות
הסבר מפורט
תשובה נכונה: ב. חוויה של "מחיר: $0.00, Beta: 0.00, המלצה: ---" היא מבלבלת ולא מקצועית. ה-hide/show מבטיח שהלוח נגלה רק אחרי populateDashboard(data) — כשכל השדות מלאים.

גם: Chart.js מצייר canvas לפי גודל הכרטיס. אם הכרטיס מוסתר בעת יצירת הגרף — הגרף עלול לצאת ממוזג. לכן chart.update() חשוב לאחר display:block.
שאלה 3 מתוך 4
מה ההבדל בין fetch עם ו-fetch בלי try/catch?
א
אין הבדל — try/catch הוא רק סגנון קידוד
ב
ללא try/catch, שגיאת רשת (API נפל, אינטרנט לא יציב) תקרוס את הדף עם הודעה טכנית. עם try/catch — תופסים השגיאה ומציגים הודעה ידידותית
ג
try/catch איטי יותר — כדאי להימנע ממנו בקוד ייצור
ד
fetch תמיד מצליח — אין צורך ב-try/catch
הסבר מפורט
תשובה נכונה: ב. fetch זורק Exception כשיש שגיאת רשת (לא כשה-API מחזיר error — זה JSON רגיל). ללא try/catch:

Uncaught (in promise) TypeError: Failed to fetch

הדף "קופא", המשתמש בהלה. עם try/catch:
catch(e) { showError("שגיאת רשת — בדקו חיבור..."); }

כלל: כל fetch = try/catch. ללא יוצא מן הכלל.
שאלה 4 מתוך 4
מדוע הפרומפט ציין 'canvas height=300px via CSS' ולא כ-attribute ב-HTML?
א
CSS עדיף מבחינת ביצועים
ב
Chart.js מתעלם מ-attribute height כשה-page הוא RTL — גובה דרך CSS בלבד מבטיח רנדור תקין
ג
attribute height הוצא מה-HTML5 standard
ד
אין הבדל — שתי השיטות שוות
הסבר מפורט
תשובה נכונה: ב. זהו באג ידוע בשילוב Chart.js + dir="rtl". כש-height מוגדר כ-attribute בלבד, Chart.js מחשב מחדש את גודל ה-Canvas לפי ה-container ב-RTL — ולפעמים מקבל גובה לא מוגדר ומתרחב לאינסוף.

#priceChart { height: 300px !important; max-height: 300px; }

CSS עוקף את חישוב גוגל ונותן גובה קבוע. !important מבטיח שChart.js לא ידרוס זאת.
